因为 Webpack 默认只能解析 JS 文件，所以我们需要使用一些第三方的 Loader 对一些资源文件进行处理。

```js
// 希望导入的模块结果是一个可用的资源路径
const path = require("./assets/template.jpeg");

console.log(path);

let img = document.createElement("img");
img.src = path;
document.body.appendChild(img);
```

例如上面的代码中，我们使用代码动态的把图片添加到页面中，并且希望 path 的值为一个可用的资源路径，但是当我们运行`npx webpack`打包的时候就会报错：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695087946043-86448c77-e3bc-4a7c-bdca-eb08cae801e1.png)

这就是因为 Webpack 默认只认识 JS 文件，对于一些图片文件它无法把图片解析为 AST 语法树，这个时候就需要使用一些 Loader 对文件进行处理啦，让 Loader 把图片文件转换为有效的 JS 代码。

## file-loader
1、安装

```bash
$ npm i file-loader -D
```

2、配置

```js
module.exports = {
  mode: "development",
  devtool: "source-map",
  module: {
    rules: [
      {
        // 对图片进行处理
        test: /\.(png|jpg|jpeg)/,
        use: ["file-loader"]
      }
    ]
  }
};

```

3、打包

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695088309763-c6c4b50b-f84d-4934-8385-f4a6d3a7febb.png)

可以看到，图片资源被正常的打包了，然后我新建一个 HTML 文件并引入 main.js 文件到浏览器查看效果：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695088428283-4d473642-1726-4ed2-9211-3ea46d8b0a5c.png)

但是图片并没有正常显示，这是因为 file-loder 把图片进行了默认导出，所以需要获取`path.default`属性。

```js
// 希望导入的模块结果是一个可用的资源路径
const path = require("./assets/template.jpeg");

console.log(path);

let img = document.createElement("img");
img.src = path.default;
document.body.appendChild(img);
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695088537410-480d6194-f7c4-446d-8c9d-0c07662d6772.png)

这时，显示正常！

当然，file-loader 也可以进行一些属性配置，例如我想把图片都放在 dist/imgs 目录下，且对图片进行自定义的命名：

```js
module.exports = {
  mode: "development",
  devtool: "source-map",
  module: {
    rules: [
      {
        test: /\.(png|jpg|jpeg)/,
        // use: ["file-loader"]
        use: [
          {
            loader: "file-loader",
            options: {
              name: "imgs/[name].[contenthash:5].[ext]"
            }
          }
        ]
      }
    ]
  }
};

```

更多配置详见：

[file-loader](https://www.npmjs.com/package/file-loader)

## url-loader
url-loader 和 file-loader 的功能基本类似，区别就是 url-loader 会把指定大小的文件转换为一个 Base64 的字符串路径而不是复杂到 dist 目录下。

1、安装

```bash
$ npm i url-loader -D
```

2、配置

```js
module.exports = {
  mode: "development",
  devtool: "source-map",
  module: {
    rules: [
      /* {
          test: /\.(png|jpg|jpeg)/,
          // use: ["file-loader"]
          use: [
              {
                  loader: "file-loader",
                  options: {
                      name: "imgs/[name].[contenthash:5].[ext]"
                  }
              }
          ]
      } */
      {
        test: /\.(png|jpg|jpeg)/,
        use: ["url-loader"]
      }
    ]
  }
};
```

3、运行打包，查看文件

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695089117846-197b85c2-9ffa-4321-98a9-c0821691a049.png)

可以看到，template.jpeg 模块默认导出一个 Base64 的字符串。

当然，url-loader 也支持一些参数的配置，它默认会把所有的图片资源全部转换为 Base64 的字符串，这显然是不合理的。

在实际的开发中，我们通常会把一些体积小的图片（例如图标图片）转换为 Base64 的字符串，而把体积稍微大的图片输出到 dist 目录下，如果依然转换为 Base64 就会造成 JS 文件非常的大，请求耗时。

例如，我更改限制，当图片资源小于 1kb 的时候才会转换为 Base64 字符串，否则就输出到 dist 目录下：

```js
module.exports = {
  mode: "development",
  devtool: "source-map",
  module: {
    rules: [
      /* {
          test: /\.(png|jpg|jpeg)/,
          // use: ["file-loader"]
          use: [
              {
                  loader: "file-loader",
                  options: {
                      name: "imgs/[name].[contenthash:5].[ext]"
                  }
              }
          ]
      } */
      {
        test: /\.(png|jpg|jpeg)/,
        // use: ["url-loader"]
        use: [
          {
            loader: "url-loader",
            options: {
              // limit 的单位是字节
              limit: 1 * 1024
            }
          }
        ]
      }
    ]
  }
};

```

这个时候运行打包，template.jpeg 就会被输出到 dist 目录下了。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695089981904-c623a29f-136a-43d5-b481-0edc60487e89.png)

当 url-loader 在处理大于 limit 指定大小的图片的时候，实际上仍然是使用 file-loader 对图片进行处理，所以 url-loader 还可以传递 file-loader 的参数，然后 url-loader 会把参数传递给 file-loader 进行处理：

```js
module.exports = {
  mode: "development",
  devtool: "source-map",
  module: {
    rules: [
      /* {
          test: /\.(png|jpg|jpeg)/,
          // use: ["file-loader"]
          use: [
              {
                  loader: "file-loader",
                  options: {
                      name: "imgs/[name].[contenthash:5].[ext]"
                  }
              }
          ]
      } */
      {
        test: /\.(png|jpg|jpeg)/,
        // use: ["url-loader"]
        use: [
          {
            loader: "url-loader",
            options: {
              limit: 1 * 1024,
              name: "imgs/[name].[contenthash:5].[ext]"
            }
          }
        ]
      }
    ]
  }
};

```

可以看到，图片按照我们的配置输出到 dist/imgs 目录下了。
