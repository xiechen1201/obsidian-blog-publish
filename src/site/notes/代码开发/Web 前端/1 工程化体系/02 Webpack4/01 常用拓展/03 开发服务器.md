目前阶段，如果我们每次更改 src 文件目录下的源码后都需要手动的执行打包命令、然后运行 html 文件，在浏览器上查看效果，整个流程太贵于复杂。

虽然我们可以通过`watch`属性来监听 src 目录下源码的更改，当代码更改后都会重新执行打包：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const HtmlWebpackPlugin = require("html-webpack-plugin");
const CopyWebpackPlugin = require("copy-webpack-plugin");

module.exports = {
  mode: "development",
  devtool: "source-map",
  entry: {
    index: "./src/index.js"
  },
  output: {
    filename: "script/[name].[chunkhash:5].js"
  },
  watch: true,
  plugins: [
    new CleanWebpackPlugin(),
    new HtmlWebpackPlugin({
      template: "./public/index.html",
      chunks: ["index"],
      filename: "index.html"
    }),
    new CopyWebpackPlugin({
      patterns: [{ from: "./public/imgs", to: "./imgs" }]
    })
  ]
};

```

这个时候当更改 src/index.js 文件内容后自动执行打包，但是仍然需要我们手动的刷新浏览器查看页面效果。并且我们有的时候还需要把打包后的代码部署带测试服务器上来模拟真实的环境，这样每次打包完成后都需要上次又会变得非常麻烦。

## 🔢 webpack-dev-server
为了解决上面的问题，Webpack 提供了 webpack-dev-server 这个库来启动一个开发环境的服务器。

它既不是 Loader 也不是 Plugin。

1、安装

```bash
# 高版本和 Webpack4 不兼容
$ npm i webpack-dev-server@3 -D
```

2、执行

```bash
$ npx webpack-dev-server
```

webpack-dev-server 和 webpack 命令基本一致，它支持 webpack 命令几乎所有的参数，可以把它当作 webpack 命令的替代品，只不过只能用于开发环境，真正打包到生产的时候，还需要使用`npx webpack`命令。

当我们运行 webpack-dev-server 的时候就会启动一个开发服务器：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695021301118-4c540920-a6b7-45cc-b561-ebec01b60f1c.png)

默认运行在  http://localhost:8080 地址！

而且，你会发现 dist 目录下根本就没有任何的文件，这是因为 webpack-dev-server 就把打包完成的文件存放在内存当中，用来模拟一个服务器的环境！

当我们执行 webpack-dev-server 命令后，它做了哪些操作呢（简化版）？

1、内部依然执行 webpack 命令，然后把参数传递给 webpack

2、开启 watch，所以 webpack.config.js 内可以不写`watch`属性

3、注册 hooks，类似于 Plugin，webpack-dev-server 会向 webpack 中注册一些钩子函数，主要功能如下：

1. 将资源列表（aseets）保存起来
2. 禁止webpack输出文件

4、用 express 开启一个服务器，监听某个端口，当请求到达后，根据请求的路径，给予相应的资源内容

## 🔢 配置
webpack-dev-server 也可以进行配置，详见：

[开发中 server(devServer)](https://v4.webpack.docschina.org/configuration/dev-server/#devserver-proxy)

下面是一些常用的配置：

1、`prot`

指定要监听请求的端口号。

```js
module.exports = {
  //...
  devServer: {
    // 默认为 8080
    port: 8080
  }
};
```

2、`proxy`

用于配置请求代理，通常用于解决一些请求跨域的问题。

在实际的项目开发中，我们的前端代码和后端代码都会部署到同一个域名下面，这个时候一般不存在跨域的问题。

而在开发环境中，由于 webpack-dev-server 启动了一个临时的服务器，就会在请求接口的时候导致跨域出现。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695022617214-c58f5c63-ee1b-402d-9c16-c8df3ca81690.jpeg)

例如图中的，域名和端口不一致就会导致跨域问题。

这个时候，我们就可以通过`proxy`属性来配置请求代理：

```js
module.exports = {
  //...
  devServer: {
    proxy: {
      '/api': 'http://testdomain.com'
    }
  }
};
```

当开发环境中出现以 /api 开头的请求时，就会被 webpack-dev-server 所捕获，然后把本次的请求转发到 http://testdomain.com 服务上。

这样配置过后就不会存在跨域问题了，因为跨域是针对浏览器的安全限制，而 webapck-dev-server 是运行在 Node 环境上的！
