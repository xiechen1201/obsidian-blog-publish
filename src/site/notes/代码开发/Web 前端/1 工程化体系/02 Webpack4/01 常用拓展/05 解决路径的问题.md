在使用 file-loader 或 url-loader 时，可能会遇到一个非常有趣的问题。

有时候我们希望把 JS、HTML、图片都放在不同的目录，让 dist 目录变得简洁一些：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  mode: "development",
  devtool: "source-map",
  output: {
    // 把 JS 文件输出到 js 目录下
    filename: "js/[name].[chunkhash:5].bundle.js"
  },
  module: {
    rules: [
      {
        test: /\.(png|jpg|jpeg)/,
        use: [
          {
            loader: "file-loader",
            options: {
              // 把图片文件输出到 imgs 目录下
              name: "imgs/[name].[contenthash:5].[ext]"
            }
          }
        ]
      }
    ]
  },
  plugins: [
    new CleanWebpackPlugin(),
    new HtmlWebpackPlugin({
      template: "./public/index.html",
      // 把 HTML 文件输出到 html 目录下
      filename: "html/index.html"
    })
  ]
};
```

src/index.js 文件内依然是动态的往页面中添加一张图片：

```js
import imgUrl from "./assets/template.jpeg";

let img = new Image();
img.src = imgUrl;
document.body.appendChild(img);
```

最后执行打包目录结构确实是我们想要的那样：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695090971256-90045baa-8e8b-444b-a220-6876b54ff28c.png)

但是当我们运行 html/index.html 文件的时候，发现图片并没有正确的被加载：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695091019335-4f047440-6541-4508-9576-e0ef27bec0d5.png)

但是 JS 文件是正常被加载的，这是为啥呢？

造成这个问题的根本原因就是模块的路径是来自于 Loader 或者 Plugin 的，当产生路径的时候只是相对于 dist 目录的，并不知道该路径将在哪个资源中使用，从而无法确定最终正确的路径。

结合上面的案例，因为图片是被 file-loader 处理，它会把图片输出到 dist/imgs 目录下，但是并不知道使用这个图片的 JS 会放在哪里，更不知道 HTML 文件会放在哪里，而图片是在 dist/main.js 内部导入的，所以就导致了图片无法被加载。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695091777981-d3e000a9-6b85-4d8a-bcd8-e008846c856a.png)

HTML 拿到 imgs/template.59ac3.jpeg 这么一段字符串路径，这是一个相对路径，所以就会到 dist/html 目录下寻找这个图片。

而 html-webpack-plugin 处理过的 HTML 文件为什么可以正常加载 JS 文件呢？

因为 html-webpack-plugin 是一个插件，它可以在事件触发的时候读取到 Webpack 最终的资源结构，所以可以灵活处理！

## 🔢 publicPath
面对这种问题就可以使用 Webpack 的一个属性 publicPath。

publicPath 属性实际上会被转换为`webpack_require__.p`属性，如果不进行配置默认就是一个空字符串：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695092249751-ef604013-4970-4806-8d24-d594d2030ca1.png)

`webpack_require__.p`属性不会被调用，而是专门提供给 Loader 和 Plugin 使用的！

有些 Loader 和 Plugin 需要使用这个属性，所以你的配置将觉得这个最终资源的路径，要谨慎使用！

例如我对 publicPath 配置为：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  mode: "development",
  devtool: "source-map",
  output: {
    filename: "js/[name].[chunkhash:5].bundle.js",
    publicPath: "../",
  },
  module: {
    rules: [
      {
        test: /\.(png|jpg|jpeg)/,
        use: [
          {
            loader: "file-loader",
            options: {
              name: "imgs/[name].[contenthash:5].[ext]"
            }
          }
        ]
      }
    ]
  },
  plugins: [
    new CleanWebpackPlugin(),
    new HtmlWebpackPlugin({
      template: "./public/index.html",
      filename: "html/index.html"
    })
  ]
};
```

最终生成的 dist/main.js 里面就会把`webpack_require__.p`设置为`../`：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695092579074-e42f5374-9513-475a-87d7-bea945ed3c55.png)

通常 Loader 和 Plugin 看到`webpack_require__.p`有值就会进行拼接处理，例如图片中的 template 的图片，简单理解为这样：

```js
let url = "";

if(webpack_require__.p){
  url = webpack_require__.p + ""
}else{
  url = ""
}
```

当拼接上`../`后，图片就可以正常显示了，因为会到上一层目录中寻找图片：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695092708281-424c5b34-d690-4a86-83af-3136a99678ff.png)

publicPath 属性值就是一个字符串，可以进行随意的书写，例如我们的资源要引入的是 CDN 地址：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
    mode: "development",
    devtool: "source-map",
    output: {
        filename: "js/[name].[chunkhash:5].bundle.js",
        publicPath: "https://cdn.jsdelivr.net/demo/",
    },
    module: {
        rules: [
            {
                test: /\.(png|jpg|jpeg)/,
                use: [
                    {
                        loader: "file-loader",
                        options: {
                            name: "imgs/[name].[contenthash:5].[ext]"
                        }
                    }
                ]
            }
        ]
    },
    plugins: [
        new CleanWebpackPlugin(),
        new HtmlWebpackPlugin({
            template: "./public/index.html",
            filename: "html/index.html"
        })
    ]
};

```

同样也会进行拼接处理：

有时，publicPath 属性也可以是一个`publicPath:"/"`，当资源部署到服务器上的时候，再发起请求的时候就会到服务器的根上寻找。

```plain
访问 index.html 加载图片，路径为 /imgs/template.jpeg
因为是在同一个服务器上，所以会自动拼接上域名：
http://testdomain.com/imgs/template.jpeg
```

所以，publicPath 是根据实际情况动态配置的，没有固定的答案。

如果 Loader 和 Plugin 的文档中也提供了 publicPath 属性，也可以使用它们提供的：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  mode: "development",
  devtool: "source-map",
  output: {
    filename: "js/[name].[chunkhash:5].bundle.js",
    // publicPath: "../",
  },
  module: {
    rules: [
      {
        test: /\.(png|jpg|jpeg)/,
        use: [
          {
            loader: "file-loader",
            options: {
              name: "imgs/[name].[contenthash:5].[ext]",
              publicPath: '../',
            }
          }
        ]
      }
    ]
  },
  plugins: [
    new CleanWebpackPlugin(),
    new HtmlWebpackPlugin({
      template: "./public/index.html",
      filename: "html/index.html"
    })
  ]
};

```
