某些时候，我们可能只想简单的把一个文件复制到另一个文件夹下面，就可以使用 copy-webpack-plugin 插件来完成。

例如，我们的 public/index.html 文件导入了一个静态的资源图片：

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <img src="./_assets/1695022617214-c58f5c63-ee1b-402d-9c16-c8df3ca81690.jpeg" alt="">
    <div id="app">This is index page.</div>
</body>
</html>
```

如果这个时候打包代码，你就会发现 dist 目录下根本没有这个资源图片：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695019343648-86084620-0f1c-4a45-9449-9471e0e00775.png)

这其实是因为图片资源是通过 HTML 文件导入的，并不是通过 JS 文件来操作的，和 JS 没有半点关系，所以就不会产生依赖关系，也就不会在打包的时候把这个图片进行打包啦！

所以，我们就希望有一个插件能把一下静态的资源，和 JS 没有交互的资源复制到 dist 目录下，这个时候就可以使用 copy-webpack-plugin 插件啦。

1、安装

```bash
# 版本太高和 Webpack4 不兼容
$ npm i copy-webpack-plugin@6 -D
```

2、配置

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const HtmlWebpackPlugin = require("html-webpack-plugin");
const CopyWebpackPlugin = require("copy-webpack-plugin");

module.exports = {
  mode: "development",
  devtool: "source-map",
  entry: {
    index: "./src/index.js"
  },
  output: {
    filename: "script/[name].[chunkhash:5].js"
  },
  plugins: [
    new CleanWebpackPlugin(),
    new HtmlWebpackPlugin({
      template: "./public/index.html",
      chunks: ["index"],
      filename: "index.html"
    }),
    new CopyWebpackPlugin({
      patterns: [
        // from 属性的路径是相对于 webpack.config.js
        // to 属性的路径是相对于 dist 目录下的
        { from: "./public/imgs", to: "./imgs" },
      ]
    })
  ]
};
```

3、运行打包，查看结果

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/01%20%E5%B8%B8%E7%94%A8%E6%8B%93%E5%B1%95/_assets/1695019667601-99c95768-38b6-4682-a2ee-1e5229a2bc28.png)

这样就把 public 下的资源图片复制到 dist 下面了！
