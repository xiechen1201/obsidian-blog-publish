模块解析主要发生在「Webpack 的编译阶段」，模块解析包括：语法抽象树分析、依赖分析、模块语法替换。

如果不对某些模块进行模块解析，那么自然就会节省一些事情：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698739694469-ea01f817-77f6-4f19-bb97-f0a3853b9fc2.png)

也就是直接进行保存转换后的代码，直接保存的是经过/不经过 Loader 处理后的代码，自然而然的就可以缩短 Webpack 的构建时间！

那么哪些模块不需要进行解析呢？

当我们的代码中使用了某些第三方按照的依赖，且这个依赖不再依赖其他的模块。而通常这些模块在发布到 npm 上面的时候已经经过了构建的处理（语法转换、代码压缩等），所以我们就不再需要对这个模块进行解析了，例如 jquery。

例如我们有这么一段代码：

```js
import $ from "jquery";
import a from "./a";

console.log($(".list .item"));
console.log(a);
```

如果，我们不进行任何的配置，看一下编译的总耗时：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698740534819-27d2f8df-f691-4934-8b5a-d17ec67b6f14.png)

要配置对某些模块不解析，要使用`module.noParse`属性，改属性是一个正则表达式用于匹配模块的路径名称：

```js
module.exports = {
  mode: "production",
  module: {
    noParse: /jquery/
  }
};
```

然后再看下构建的总耗时：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698740861577-03bc39d2-e98d-4b03-bcbb-9d61fc6c4b66.png)

可以看到前后的对比有明显的提示！

但是，`module.noParse`属性也不能滥用，例如我们有一个 ./src/test.js 文件内容是这样的：

```js
import $ from "jquery";
import "./test";
```

```js
import $ from "jquery";
console.log($);
```

然后我们配置对 test 模块不进行解析：

```js
module.exports = {
  mode: "development",
  module: {
    noParse: /test/
  }
};
```

然后查看 ./dist/main.js 文件就会发现 test 模块的代码并没有进行转换：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698741952506-2503ed56-6b55-47cd-a6d3-9a7e1f7d05af.png)

这样就会导致在低版本的浏览器中无法运行。所以，必须是没有依赖的模块、并且不需要进行模块解析的才可以进行排除！
