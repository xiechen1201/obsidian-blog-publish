## 🔢 基本原理
自动分包和手动分包不同，自动分包是从实际的角度出发，从一个更加宏观的角度来控制分包，而不是针对某个具体的包分出去进行控制。

自动分包的关键是要配置一个合理的分包策略。

有了分包策略之后，不需要额外安装任何插件，Webpack 会自动按照策略进行分包。

Webpack 内部集成使用的是 SplitChunksPlugin 这个插件进行分包。

<br/>

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698906299595-f570650c-447b-4fbe-b977-bee088363c35.png)

从分包的流程图中可以看到：

- 分包的策略极为重要，它决定了如何进行分包；
- 分包的时候 Webpack 开启了一个新的 Chunk，对分离的模块进行打包；
- 打包结果中，公共的代码会被提取出来形成一个单独的文件，它是新 chunk 的产物；

## 🔢 分包策略的基本配置
分包策略是通过`optimization`属性进行配置一些优化信息。

```js
module.exports = {
  mode: "development",
  optimization: {
    splitChunks:{
      // 具体的配置
    }
  }
};
```

实际上，分包策略具有它默认的配置，通常不需要进行大幅度的更改即可应对大部分的场景，主要常用属性如下：

## 🔢 1、chunks
该属性用于配置什么样的场景需要使用分包策略，可选：

- all，对所有的 chunk 都要使用分包策略
- async，默认值，只对异步的 chunk 使用分包策略
- initial，只对普通的 chunk 使用分包策略

所以，默认下 Webpack 只会对异步的 chunk 进行分包，如果我们想对所有的 chunk 都进行分包把`chunks: all`即可。

例如我这里有两个入口 chunk：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  mode: "development",
  plugins: [new CleanWebpackPlugin()],
};
```

就是一个很简单的配置，先看一下没有分包的资源大小。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698907163323-3c6c5a47-2f9d-4cd3-bf2c-1aca25b80bde.png)

然后我们配置`chunks: all`对 jquery 和 lodash 进行分包：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  mode: "development",
  plugins: [new CleanWebpackPlugin()],
  optimization: {
    splitChunks: {
      chunks: "all"
    }
  }
};

```

从控制台可以看到，Webpack 在构建的时候发现了公共的模块，然后产出一个新的 chunk 命名为 vendors~index~list.js，这样 index.js 和 list.js 文件立竿见影的减小了。

vendors 就是对 node_modules 下公共模块的汇总集合。

## 🔢 2、maxSize
该属性主要用来控制 chunk 包的大小，单位是字节。

如果某个包（包括分出来的包）超过了设定的字节数，那么 Webpack 会尽最大的努力对这个包再次进行分包！

需要注意的是，分包策略的基础单位还是模块，如果一个完整的模块超过了设定的大小，它是无法再进行分割的。所以，尽管使用了这个配置，完全有可能某个包还是超过了设定的大小！！！

<br/>

例如对前面的 vendors~index~list.js 包进行控制，他目前是 867KiB 我们想要设置如果超过了 500KiB 那么就再次进行分包：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  output: {
    filename: "[name].[chunkhash:3].js"
  },
  mode: "development",
  plugins: [new CleanWebpackPlugin()],
  optimization: {
    splitChunks: {
      chunks: "all",
      maxSize: 500 * 1024
    }
  }
};
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698908826967-4a25a7b9-ad83-4ead-aa4d-d5b5086c04c9.png)

可以看到 Webpack 对 vendors 这个 chunk 尽量的进行分包，但是仍然有一个包是大于 500KiB 的！

所以，这也符合我们上面说的 Webpack 分包策略是基于模块为单位的。

该配置相对来说意义不大，因为它只会把一个包分包多个包，但是包的总体积没有发生根本的变化。

## 🔢 4、minChunks
改属性用于配置一个模块被多少个 chunk （注意是 chunk 不是模块，chunk 是由多个模块组成的）使用的时候才会进行分包，默认是 1。

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  mode: "development",
  plugins: [new CleanWebpackPlugin()],
  optimization: {
    splitChunks: {
      chunks: "all",
      // maxSize: 500 * 1024,
      // automaticNameDelimiter: "+",
      minChunks: 1
    }
  }
};

```

## 🔢 5、minSize
改属性用于配置分包的时候达到多少字节后才被分包，默认值为 30000 字节。

如果某个包的大小没有超过这个设定则不会进行分包处理。

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  mode: "development",
  plugins: [new CleanWebpackPlugin()],
  optimization: {
    splitChunks: {
      chunks: "all",
      // maxSize: 500 * 1024,
      // automaticNameDelimiter: "+",
      // minChunks: 1,
      minSize: 30000
    }
  }
};

```

## 🔢 缓存组
前面那些配置都是对全局生效的，实际上分包策略是基于缓存组的。每个缓存组提供一套独有的策略，Webpack 按照缓存组的优先级依次处理，被缓存组处理过的分包不再进行处理！

默认情况下，Webpack 提供了两个缓存组：

```js
module.exports = {
  optimization:{
    splitChunks: {
      // 一些全局配置
      cacheGroups: {
        // 属性名是缓存组名称，会影响到分包的 chunk 名
        // 属性值是缓存组的配置，「缓存组继承所有的全局配置，也有自己特殊的配置」
        vendors: {
          // 凡是全局配置的条件+正则匹配的时候，就会执行该组的分包
          test: /[\\/]node_modules[\\/]/,
          // 缓存组优先级，优先级越高，该策略越先进行处理，默认值为0
          priority: -10
        },
        default: {
          // 覆盖全局配置，将最小 chunk 引用数改为 2
          minChunks: 2,
          // 优先级
          priority: -20,
          // 已经被分包出去 chunk 就不要再重新分离，防止分离相同的 chunk
          reuseExistingChunk: true
        }
      }
    }
  }
}
```

通常情况下，默认的缓存组配置以及够用了，但是我们依然可以使用缓存组来完成一些事情，例如公共样式的抽离：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const MiniCssExtractPlugin = require("mini-css-extract-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  mode: "development",
  module: {
    rules: [
      {
        test: /\.css$/,
        exclude: /node_modules/,
        use: [MiniCssExtractPlugin.loader, "css-loader"]
      }
    ]
  },
  plugins: [new CleanWebpackPlugin(), new MiniCssExtractPlugin()],
  optimization: {
    splitChunks: {
      chunks: "all"
      // maxSize: 500 * 1024,
    }
  }
};

```

```js
import "./common.css"
import "./index.css";

// 判断是不是一个数组
const result = _.isArray($(".red"));
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698910723792-04d761e5-2a47-4fde-88bd-c927fe491504.png)

可以看到，common.css 文件没有被打包出来而是混合到了 index.css 和 list.css 文件中了。

我们可以配置一个缓存组，让 common.css 文件单独存在：

```js
const { CleanWebpackPlugin } = require("clean-webpack-plugin");
const MiniCssExtractPlugin = require("mini-css-extract-plugin");

module.exports = {
  // mode: "production",
  entry: {
    index: "./src/index.js",
    list: "./src/list.js"
  },
  mode: "development",
  module: {
    rules: [
      {
        test: /\.css$/,
        exclude: /node_modules/,
        use: [MiniCssExtractPlugin.loader, "css-loader"]
      }
    ]
  },
  plugins: [
    new CleanWebpackPlugin(),
    new MiniCssExtractPlugin({
      // 配置的是 chunk 的名称
      filename: "[name].[chunkhash:5].css",
      // 配置的是分包 chunk 的名称
      chunkFilename: "common.[chunkhash:5].css"
    })
  ],
  optimization: {
    splitChunks: {
      chunks: "all",
      // maxSize: 500 * 1024,
      cacheGroups: {
        // 新增一个针对公用 CSS 的缓存组
        styles: {
          minSize: 0,
          test: /\.css/,
          minChunks: 2
        }
      }
    }
  }
};
```

但是却多出一个 style~index~list.js 的 JS 文件？

这是为了应对 css-loader 可能开启了 CSS Module，所以该 JS 文件是为了满足 CSS Module 的。

## 🔢 原理
大致原理如下：

- 检查每个 chunk 的编译结果
- 根据分包策略，找到满足策略的模块
- 根据分包策略，生成新的 chunk 打包这些模块（代码有所变化）
- 把打包出去的模块从原始模块中移除
