为什么要进行代码压缩？

可以减小代码文件的体积、破坏代码的可阅读性保护知识产权。

通常，在生产环境时候我们需要对代码进行压缩。

目前最主流的两个压缩工具是 UglifyJs 和 Terser。

- UglifyJs 是一个传统的代码压缩工具，已存在多年，曾经是前端应用的必备工具，但由于它不支持ES6 语法（因为它认为可以通过 babel 对代码进行转换然后再使用 UglifyJs 压缩，但是某些情况可能不会使用 babel 进行转换），所以目前的流行度已有所下降。
- Terser 是一个新起的代码压缩工具，支持 ES6+ 语法，因此被很多构建工具内置使用。Webpack 安装后会内置 Terser，当启用生产环境后即可用其进行代码压缩。

[https://terser.org/](https://terser.org/)

既然 Webpack 以及内置了压缩，我们为什么还要学习呢？

这是为了某些情况下我们想要更改、添加压缩工具，又或者是相对 Terser 进行配置，就需要使用`optimization.minimizer`属性进行配置：

```js
const TerserPlugin = require('terser-webpack-plugin');
const OptimizeCSSAssetsPlugin = require('optimize-css-assets-webpack-plugin');

module.exports = {
  optimization: {
    // 是否要启用压缩，默认情况下，生产环境会自动开启
    minimize: true,
    // 压缩时使用的插件，可以有多个
    minimizer: [
      new TerserPlugin(),
      new OptimizeCSSAssetsPlugin()
    ]
  }
};
```
