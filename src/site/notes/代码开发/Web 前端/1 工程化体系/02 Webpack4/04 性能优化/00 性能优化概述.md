Webpack 中的性能概述主要体现在三个方面：

1、构建性能

构建性能指的是「开发阶段时候的构建性能」，而不是生产环境的构建性能。

为什么需要关注开发阶段的构建性能呢？

这是因为 Webpack 只有通过编译打包我们才能在页面中看到最终运行的效果，如果我们每次都只更改一行或者几行代码想要在页面中查看实时的效果，那么就需要等待 Webpack 重新编译后刷新浏览器页面。如果这个阶段编译的太慢，那么就会极大的降低我们的开发效率。

所以，构建阶段的优化就是为了降低编译的过程耗时！

2、传输性能

传输性能指的是打包后的 JS 文件传输到浏览器上的时间。

在这个角度要考虑到：

- 总体传输量：所有需要传输的 JS 文件内容总量加起来应该尽量的「小」，减少重复的代码；
- 文件数量：用户访问页面的时候，需要传输的 JS 文件数量应该尽量的「少」，文件越多，HTTP 的请求就会变多，响应速度就会变慢；
- 浏览器缓存：JS 文件会被浏览器进行缓存，被缓存的资源可以减少对服务器的请求；

3、运行性能

运行性能指的是 JS 在浏览器中的运行速度。

这块内容和 Webpack 关系不大，主要取决于我们书写的 JS 代码。
