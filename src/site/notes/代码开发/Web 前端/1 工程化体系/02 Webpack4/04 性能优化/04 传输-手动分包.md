分包属于传输性能的优化，这是因为打包后的文件体积越小浏览器的请求时间就会变得更短，另外就是把一些不会经常变动的代码单独打包为一个文件，充分利用浏览器的缓存。

什么是分包？

简单说就说讲一个整体的代码，分到不同的打包文件中去。

举例：

```js
import $ from "jquery";
import _ from "lodash";

// 判断是不是一个数组
const result = _.isArray($(".red"));
console.log(result);
```

正常这样打包会把 index.js、jquery、lodash 的代码全部打包到 ./dist/main.js 文件中去，该文件就会变得非常大，在传输过程影响性能！

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698896623660-dd9fde3b-1a1a-4b9a-a236-de3c6e8a4bbc.png)

例如这个时候又一个 chunk 依赖了 jquery 和 lodash 这两个模块又会导致模块的重复打包。这个时候两个 bundle 文件都包含了 jquery 和 lodash 模块，虽然不会影响最终的运行结果，但是严重的影响了打包的体积。

所以，我们就要解决把公共模块代码抽离为一个单独的 bundle，充分的利用浏览器的缓存。

总结一下：

- 为什么需要分包？
    - 提取公共模块代码，降低总体积；
    - 充分利用浏览器的缓存，浏览器不需要每次都去服务器获取资源；
- 什么时候需要分包？
    - 多个 chunk 引用了相同的模块时候；
    - 公共模块体积比较大，基本不会改动的时候；
- 如何分包？
    - 手动分包（本文内容）
    - 自动分包

## 🔢 基本原理
## 🔢 1、先对公共的模块进行单独的打包
![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698895046281-5fcfbcfa-ef61-4882-9d41-2017c4e0806b.png)

这一步会把 jquery 与 lodash 进行单独的单独的打包，然后让打包结果暴露出一个变量。

我们可以新一个 webpack.dll.config.js 文件，专门用来打包这些公共的模块：

```js
const webpack = require("webpack");
const path = require("path");

module.exports = {
  mode: "production",
  // 配置公共模块进行的入口
  entry: {
    jquery: ["jquery"],
    lodash: ["lodash"]
  },
  // 配置公共模块的结果放在 dist/dll 目录下
  output: {
    filename: "dll/[name].js",
    library: "[name]" // 每个 bundle 暴露的全局变量名
  },
  plugins: [
    // 生成一个资源清单
    new webpack.DllPlugin({
      path: path.resolve(__dirname, "dll", "[name].manifest.json"),
      name: "[name]"
    })
  ]
};
```

手动分包主要是使用 webpack.DllPlugin 这个插件来帮助我们生成一个资源清单 JSON 文件。

资源清单的作用：

我们目前已经对 jquery 和 lodash 进行了单独的打包，当我们下次正常执行`npx webpack`的时候，Webpack 依然会在 ./src/index.js 文件中发现导入了 jquery 和 lodash 模块，但是它会先读取资源清单查看是否已经对 jquery 和 lodash 进行了打包，如果已经进行了处理，那么 Webpack 不会再把这两个模块打包到 ./dist/main.js 模块中去（这一步还未完成）！

## 🔢 2、根据入口模块正常打包
下面就要告诉 Webpack 构建的时候到哪里去查找资源清单：

因为我们正常执行构建的时候依然读取的是 webpack.config.js 文件，所以需要在该文件内进行配置。使用 webpack.DllReferencePlugin 来告诉 Webpack 构建的时候到哪里读取资源清单。

```js
const webpack = require("webpack");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  // mode: "production",
  mode: "development",
  module: {
    rules: [
      {
        test: /\.css/,
        use: ["style-loader", "css-loader"]
      }
    ]
  },
  plugins: [
    new webpack.DllReferencePlugin({
      manifest: require("./dll/jquery.manifest.json")
    }),
    new webpack.DllReferencePlugin({
      manifest: require("./dll/lodash.manifest.json")
    }),
    new HtmlWebpackPlugin({
      template: "./public/index.html"
    })
  ]
};
```

## 🔢 3、导入公共模块
由于 jquery 和 lodash 模块被单独打包了出去，所以我还需要再在 HTML 文件中导入这两个模块否则页面是无法使用这两个库的！

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Webpack App</title>
  </head>
  <body>
    <script src="./dll/jquery.js"></script>
    <script src="./dll/lodash.js"></script>
  </body>
</html>
```

然后使用 HtmlWebpackPlugin 插件使用这个模块文件：

```js
const webpack = require("webpack");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  mode: "development",
  module: {
    rules: [
      {
        test: /\.css/,
        use: ["style-loader", "css-loader"]
      }
    ]
  },
  plugins: [
    new webpack.DllReferencePlugin({
      manifest: require("./dll/jquery.manifest.json")
    }),
    new webpack.DllReferencePlugin({
      manifest: require("./dll/lodash.manifest.json")
    }),
    new HtmlWebpackPlugin({
      template: "./public/index.html"
    })
  ]
};

```

这样打包后的结果就可以把 3 个 bundle 全部加载进来了。

## 🔢 4、清理构建目录
在之前的流程中，我们使用 CleanWebpackPlugin 插件每次在构建的时候先把上一次的 dist 目录删除掉，可是到这里的手动分包就不再适用了。

我们不能让 CleanWebpackPlugin 直接把整个 dist 目录都删除，而是有选择进行删除。

```js
const webpack = require("webpack");
const HtmlWebpackPlugin = require("html-webpack-plugin");
const { CleanWebpackPlugin } = require("clean-webpack-plugin");

module.exports = {
  mode: "development",
  module: {
    rules: [
      {
        test: /\.css/,
        use: ["style-loader", "css-loader"]
      }
    ]
  },
  plugins: [
    new webpack.DllReferencePlugin({
      manifest: require("./dll/jquery.manifest.json")
    }),
    new webpack.DllReferencePlugin({
      manifest: require("./dll/lodash.manifest.json")
    }),
    new HtmlWebpackPlugin({
      template: "./public/index.html"
    }),
    new CleanWebpackPlugin({
      // 清空 dist 目录，但是排除 dll 和 dll/* 的内容
      cleanOnceBeforeBuildPatterns: ["/*", "!dll", "!dll/*"]
    })
  ]
};

```

到这里就完成了对手动分包的操作！

## 🔢 总结
1. 新建一个配置文件，针对公共模块进行单独打包，一定要开启`module.library`否则不会生成全局的变量。
2. 使用 webpack.DllPlugin 插件来生成资源清单
3. 使用 webpack.DllReferencePlugin 查找引用资源清单

需要注意的是：

- 资源清单不参与源码的直接运行，而是提供给 Webpack 构建时候使用
- 产出的公共模块必须通过手动导入
- 不要针对小型的公共模块进行使用

优点：

- 极大提升了自身模块的打包速度
- 极大缩小自身文件体积
- 有利于浏览器缓存第三方库的公共代码

缺点：

- 使用比较繁琐
- 如果第三方库包含重复代码，则效果不理想
    - ![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698905663475-d476b3fa-1040-4ecd-8d8e-9e9fa61ef574.png)
    - 这个时候，模块 A 和 B 都打包了 C 的代码，那么还需要对 C 这个模块进行单独的手动分包
