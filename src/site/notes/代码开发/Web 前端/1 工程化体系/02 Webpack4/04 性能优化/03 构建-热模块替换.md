> 首先必须说明一下，热模块（Hot Module Replace）并不能降低构建的时间，甚至可能还会增加构建的时间，但是它可以降低代码改动后到浏览器更新的时间。
>

我们前面学习过 webpack-dev-server 用来帮助我们在开发阶段启动一个服务器，大致流程如下：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698889550861-07b178e5-34ca-459c-91bc-79f6de781fde.png)

可以看到，目前当我们启动 devServer 服务器后，Webpack 会监听我们的文件当我们更改代码后 Webpack 会充值执行打包然后刷新浏览器，呈现最新的效果。如果我们的项目比较大的时候，整个构建时间是非常耗时的，降低的降低了我们的开发效率。

而有了热模块更新后，整个流程是这样的：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698889739531-41c982ab-5b89-4805-9d29-28599c8f4ec3.png)

最大的改动就是，浏览器不需要等待 Webpack 重新构建而是直接请求改动的资源即可，由于浏览器不会刷新页面，资源也就不会重新请求了！

## 🔢 使用和原理
如何开启 Hot Module Replace 呢？

```js
const webpack = require("webpack");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  mode: "development",
  devServer: {
    hot: true
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: "./public/index.html"
    }),
    // HotModuleReplacementPlugin 是可选的，因为在 Webpack4 中开启了 hot: true 默认就开启了这个插件
    new webpack.HotModuleReplacementPlugin()
  ]
};
```

这个时候需要使用 Webpack 的 API 来实现模块更新：

```js
// 是否开启了热更新
if (module.hot) {
  // 接受热更新
  module.hot.accept();
}

console.log("随便写的什么东西！");
```

这个时候查看页面效果：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698891287210-1980ce4f-8507-4be7-91f9-b0112647a19a.gif)

可以看到，我们更改`console.log`的内容后页面并不会进行刷新，页面中文本框输入也没有丢失！！！

其原理也很简单，当配置中开启了热更新后，webpack-dev-server 会向打包结果注入`module.hot`属性。

大家可能会存在疑问，module 这个全局变量是从哪里来的？

我们使用`npx webpack`（development 模式）进行打包，到 ./dist/main.js 文件中寻找答案。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/04%20%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96/_assets/1698891738174-899e788f-3da9-443d-b988-145fa758bbed.png)

这是因为 Webpack 在进行构建的时候会把我们的代码进行分析，把每个模块（也就是 ./src/index.js）都封装一个对象，对象的 key 就是模块的文件路径，对象的 value 就是一个函数，函数内是模块的代码。

Webpack 给每个模块函数传递了 3 个参数，所以模块执行的时候是可以拿大 module 这个变量的！

默认情况下，webpack-dev-server 不管是否开启了 hot 都会使用`location.reload`来刷新页面，但是如果执行了`module.hot.accpet()`就会阻止页面的刷新。

`module.hot.accpet()`的作用就是让 webpack-dev-server 通过 websoket 管道，当监听到内容更新后把最新的内容发送到浏览器，然后把接收到的结果交给 HotModuleReplacementPlugin 插件进行代码注入，把最新的模块代码替换到旧的模块代码，重新执行一次！

所以，热模块替换发生在代码运行期间。

## 🔢 样式热替换
如果想要实现 CSS 的热模块更新则必须使用 style-loader 而不是 mini-css-extract-plugin 插件，这是因为热模块更新的时候 HotModuleReplacementPlugin 只会简单的运行模块代码，所以 style-loader 代码运行后页面样式也就更新了。而 mini-css-extract-plugin 插件会把样式单独提取为一个个的文件，生成文件则是在 Webpack 构建过程中完成的，运行期间是无法更改文件的，所以该插件也就无法完成热模块更新了。

```js
const webpack = require("webpack");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  mode: "development",
  devServer: {
    hot: true
  },
  module: {
    rules: [
      {
        test: /\.css/,
        use: ["style-loader", "css-loader"]
      }
    ]
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: "./public/index.html"
    }),
    new webpack.HotModuleReplacementPlugin()
  ]
};
```

```js
// 导入 CSS 文件
import "./index.css"

// 是否开启了热更新
if (module.hot) {
  // 接受热更新
  module.hot.accept();
}

console.log("随便写的什么东西");
```

```css
input{
  border: 5px solid darkblue;
}
```
