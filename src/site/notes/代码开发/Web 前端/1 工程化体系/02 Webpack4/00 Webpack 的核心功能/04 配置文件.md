Webpack 执行 CLI 的时候可以添加很多的参数，但是如果每一个参数都添加在 CLI 上就会变得非常的麻烦，Webpack 还可以通过一个配置文件的形式来告诉 Webpack 如何执行。

运行`npx webpack`的时候默认读取的是当前目录下的 webpack.config.js 文件作为配置文件。

还可以在 CLI 中通过`--config`参数更改为一个指定的文件：

```bash
$ npx webpack --config test.config.js
```

因为 Webpack 是「运行」在 Node 环境中的，所以 webpack.config.js 中必须是 NodeJS 的代码。

这里需要分清楚：Webpack 是帮助我们打包的工具，是帮我们把开发时候的代码「打包」为可以运行在浏览器上的代码，而 Webpack 打包这个过程是运行在 Node 环境中的，所以必须书写 Node 代码。

具体一点，如果你的 ./src/index.js 文件中有这么一段代码：

```js
let obj = null;
obj.sayHi();
```

这段代码运行在浏览器上的时候肯定会报错，但是 Webpck 打包的时候不会，因为 Webpack 只会把源代码进行打包而不会运行源代码，最终生成的 dist 文件夹才是运行文件，是脱离 Node 环境的。

因为 Webpack 运行在 Node 环境，所以配置文件需要使用 CommonJS 导出：

```js
module.exports = {
    // 指定打包模式
    mode: "development"
};
```

如果 CLI 和 Webpack 的参数冲突，那么优先 CLI 的参数：

```bash
$ npx webpack --mode=production
```

这个时候，虽然 webpack.config.js 文件指定打包模式为 development，但是会以 production 的模式打包。

先简单的认识几个参数：

1、mode：编译模式，字符串，取值为 development 或 production，指定编译结果代码运行的环境，会影响 Webpack 对编译结果代码格式的处理。

2、entry：入口，字符串，指定入口文件。

3、output：输出文件，对象，指定编译结果文件。

Webpack 的大致运行流程：

执行 Webpack ==> 寻找配置文件 ==> 执行配置文件（必须是 Node 代码） ==> 寻找入口文件，读取代码，但是不会执行只是分析代码的依赖关系 ==> 代码打包，形成打包结果
