某些时候，我们可能需要针对生产环境和开发环境分别书写不同的 Webpack 配置内容。我们可以新建两个配置文件，然后通过 CLI 的`--config`参数来指定不同环境的配置文件：

```js
module.exports = {
    mode: "development",
    devtool: "source-map"
};
```

```js
module.exports = {
    mode: "production",
    devtool: "none"
};
```

```json
{
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1",
    "dev": "webpack --config webpack.dev.js",
    "prod": "webpack --config webpack.prod.js",
  }
}
```

这样我们运行`npm run dev`或者`npm run prod`就可以执行不同的配置文件啦！

除了这样的方式，Webpac 还允许配置文件导出一个函数：

```js
module.exports = env => {
  return {
    //配置内容
  }
}
```

该函数会在 Webpack 运行的时候执行，函数返回的对象将作为 Webpack 的配置内容！

在调用 Webpack 函数时，Webpack 会向函数传入一个参数`env`，该参数的值来自于 Webpack 命令中给`env`指定的值，例如：

```bash
$ npx webpack --env abc # env: "abc"

$ npx webpack --env.abc # env: {abc: true}
$ npx webpack --env.abc=1  # env: {abc: 1}
$ npx webpack --env.abc=1 --env.bcd=2 # env: {abc: 1, bcd: 2}
```

例如更改 package.json 的配置：

```json
{
  "scripts": {
    "dev": "webpack --env.dev",
    "prod": "webpack --env.prod"
  }
}
```

然后我们就可以通过`env`来判断当前的环境：

```js
module.exports = (env) => {
  console.log(env);

  if (env && env.prod) {
    return {
      mode: "production",
      devtool: "none"
    };
  } else {
    return {
      mode: "development",
      devtool: "source-map"
    };
  }
};
```

如果有相同的配置，也可以使用进行合并：

```js
const commonConfig = require("./webpack.common.js");
const devConfig = {
  mode: "production",
  devtool: "none"
}
const prodConfig = {
  mode: "development",
  devtool: "source-map"
};

module.exports = (env) => {
  console.log(env);

  if (env && env.prod) {
    return {
      ...commonConfig,
      ...devConfig
    };
  } else {
    return {
      ...commonConfig,
      ...prodConfig
    };
  }
};
```
