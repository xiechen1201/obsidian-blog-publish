## context
```js
module.exports = {
    context: path.resolve(__dirname, "src")
};
```

`context`属性的配置会影响到入口和 Loader 的解析，入口和 Loader 的相对路径会以`context`的配置作为基准路径。

`context`的默认路径就是 webpack.config.js 的路径，所以`entry`需要指定从当前路径寻找 chunk，例如：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/00%20Webpack%20%E7%9A%84%E6%A0%B8%E5%BF%83%E5%8A%9F%E8%83%BD/_assets/1694593928780-98763acd-8a8e-49b0-8f35-a654184007f0.png)

```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    entry:{
        main: "./src/index.js"
    }
};
```

当更改`context`书写后，配置文件的寻找路径就会发生变化：

```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    context: path.resolve(__dirname, "src"),
    entry:{
        main: "./index.js"
    }
};
```

不再需要`./src`了，因为默认就去到 src 文件夹下面寻找！！！

## output.library
```js
module.exports = {
    output:{
      library: "testName"
    }
};
```

该属性会把自动执行函数的返回内容暴露给一个`testName`的变量。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/00%20Webpack%20%E7%9A%84%E6%A0%B8%E5%BF%83%E5%8A%9F%E8%83%BD/_assets/1694594256509-c64c130c-085d-436b-9927-d376303cef43.png)

这样，`testName`就可以得到入口模块`src/index.js`导出的结果。

该配置开发的时候没有啥用处，某些情况下会有用：

1、和一些插件联合使用，插件要求必须提供一个xxx的全局变量

2、开发一个工具库提供给别人使用的时候（例如 jQuery），这样别人直接通过`<script src="xxx"></script>`来引入我们产生的 dist/main.js 文件后就可以直接使用`testName`变量了！

## output.libraryTarget
```js
module.exports = {
    output:{
        library: "testName",
        libraryTarget: "var",
    }
};
```

`libraryTarget`可以更加精细的控制如何把`testName`这个变量暴露出去。

其他可用的值有：

- var：默认值，暴露给一个普通变量
- window：暴露给 window 对象的一个属性
- this：暴露给 this 的一个属性
- global：暴露给 global 的一个属性
- commonjs：暴露给 exports 的一个属性

其他详见：

[输出(output)](https://v4.webpack.docschina.org/configuration/output/#output-librarytarget)

## target
```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    target: "web" // 默认值
};
```

因为 Node 和浏览器代码都可以用 JavaScript 编写，所以 Webpack 提供了多种部署 target(目标)。

可选值详见：

[构建目标(targets)](https://v4.webpack.docschina.org/configuration/target/)

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/00%20Webpack%20%E7%9A%84%E6%A0%B8%E5%BF%83%E5%8A%9F%E8%83%BD/_assets/1694594924568-eea94628-882b-4943-800c-4c1932c5a8d8.png)

## module.noParse
```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    module: {
        noParse: /jquery/
    }
};
```

```js
const $ = require("jquery");
console.log($);
```

该配置配置的是不解析某些模块，不需要对这些模块进行加载，直接把 jquery 的源码放在模块内容中就好了。

因为（例如）jQuery 这种库代码体积比较大，Webpack 分析会比较耗费时间，且 jQuery 的包已经被构建工具处理过，因此也就没有必要再让我们的 Webpack 进行加载分析依赖了。

该配置常用来忽略那些大型的单模块库，以提高构建性能。

## externals
```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    externals: {
        jquery: "$"
    }
};
```

该配置可以用来优化我们的 bundle 文件大小的。

如果不进行配置，当我们的工程代码中导入了 jQuery 最后的打包结果就会导致 bundle 文件非常的大：

```js
const $ = require("jquery");
console.log($);
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/00%20Webpack%20%E7%9A%84%E6%A0%B8%E5%BF%83%E5%8A%9F%E8%83%BD/_assets/1694595964334-c1e2b413-b57c-46b6-975b-219eb5923d04.png)

可以看到最终的代码会把 node_modules 下的 jQuery 源码全部拿进来导致代码有 10831 行。

当我们配置了`externals`后，bundle 文件中的 jquery 模块只有一行代码，导出一个`$`：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/00%20Webpack%20%E7%9A%84%E6%A0%B8%E5%BF%83%E5%8A%9F%E8%83%BD/_assets/1694596085287-a729293d-ad9c-4178-aa3a-cc506a7661dc.png)

这样，我们直接在 HTML 文件中通过 CDN 的方式导入 jQuery 即可，可以很好的减小文件的体积：

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <script src="http://libs.baidu.com/jquery/2.0.0/jquery.min.js"></script>
    <script src="./main.js"></script>
</body>
</html>
```

所以，`externals`比较适用于一些第三方库来自于外部 CDN 的情况，这样一来，即可以在页面中使用CDN，又让 bundle 的体积变得更小，还不影响源码的编写。

## resolve.modules
```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    resolve: {
        modules: ["node_modules", "self-modules"]
    }
};
```

该配置用来配置 Webpack 分析模块依赖时，看到`require()`或者`import`的导入路径， `resolve.modules`的默认值就是`node_modules`，只不过我们新增了一个`self-modules`。

这个时候，当进行裸导入的时候，Webpack 首先就会到`node_modules`目录下按照 Node 的规则寻找，如果找不到就会到`self-modules`目录下寻找。

```js
// 裸导入
require("lodash");
```

## resolve.extensions
```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    resolve: {
        extensions: [".ts", ".tsx", ".js", ".jsx"],
    }
};
```

Webpack 到查找依赖的时候，会按照`extensions`配置的后缀名进行补全，所以我们导入模块的时候可以省略后缀名。

```js
// 查找 testfile.ts testfile.tsx testfile.js testfile.jsx 的文件
require("./testfile");
```

## resolve.alias
```js
module.exports = {
  resolve: {
    alias: {
      "@": path.resolve(__dirname, "src")
    }
  }
};
```

该配置用来配置 Webpack 查找模块时候的别名。

有些时候，我们的目录嵌套的非常深，如果想要导入一个文件就需要使用`../`向上查找：

```js
require("../../../../src/demo.js");
```

当配置`alias`后就方便多了：

```js
require("@/demo.js");
```

`@`直接就表示绝对路径下面的 src 目录了！

## stats
```js
module.exports = {
    mode: "development",
    devtool: "source-map",
    stats: "errors-only"
};
```

`stats`用来配置控制台的输出，例如我配置的是只有发错误的时候才会输出。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/00%20Webpack%20%E7%9A%84%E6%A0%B8%E5%BF%83%E5%8A%9F%E8%83%BD/_assets/1694597060576-f71fe778-daae-4b0c-8518-df45cb25898e.png)

可以看到控制台非常的干净，啥都没有！

stats 还可以是一个对象进行更加精细的配置：

```js
module.exports = {
  mode: "development",
  devtool: "source-map",
  stats: {
    // 未定义选项时，stats 选项的备用值(fallback value)（优先级高于 webpack 本地默认值）
    all: undefined,
    // 添加资源信息
    assets: true,
  };
```

更多配置详见：

[统计信息(stats)](https://v4.webpack.docschina.org/configuration/stats/)
