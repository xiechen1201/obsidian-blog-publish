某些情况下依赖关系可能是这样的：

```js
if (Math.random()) {
  // 动态依赖
  const a = require("./utils/a");
  console.log(a);
}
```

以上代码，只有在代码运行的时候才能确定模块的依赖关系，如果不允许是无法确定的。

面对这样的动态依赖 Webpack 会直接把 ./utils/a.js 模块进行打包，因为 Webpack 不确定是否真的会进行导入。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699256549330-2ab3ec8b-9f42-41ae-aa19-a12ccaac4a09.png)

那么什么是不确定的动态依赖呢？假如我们写了一段代码，让用户输入去加载具体的模块。

```js
const moduleName = document.getElementById("#txt").value;

if (Math.random()) {
  const a = require("./utils/" + moduleName);
  console.log(a);
}
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699256769335-3ec7ea6a-1a7a-40d9-b15a-7b80d6dc29dc.png)

这个时候，Webpack 依然是无法进行依赖分析，因为这是用户手动输入的，无法确认最终到底要依赖的模块，这也就是不确定的动态依赖。

这个时候，Webpack 会把 ./utils 下面所有的模块都进行打包进来，以应对需要的时候能够正常的加载。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699257049256-d3810ead-2bb6-445b-99f8-d849780d4103.png)

而且，会在 dist/main.js 文件中又新创建了一个模块`"./src/utils sync recursive ^\\.\\/.*$"`，改模块内定义了一个映射对象：

```js
var map = {
	"./a": "./src/utils/a.js",
	"./a.js": "./src/utils/a.js",
	"./b": "./src/utils/b.js",
	"./b.js": "./src/utils/b.js",
	"./c": "./src/utils/c.js",
	"./c.js": "./src/utils/c.js"
};
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699257210129-be67ad81-aaf1-47ea-98cd-c11064986f39.png)

所以，面对这种不确定的动态依赖的时候，我们要手动的缩小大致的加载目录，然后把目录下的模块全部打包进来。

其实动态加载的本质就是重写了`require("./utils/" + module);`方法：

```js
// require("./utils/" + module);
// 重写为
require.context("./utils/");
```

`require.context()`仅在 Webpack 运行的过程中有效，是为了让 Webpack 把目录下的模块全部进行打包。

`require.context()`的参数：

- String，表示要把哪个目录下的模块添加到打包结果中去
- Boolean，表示是否要进行目录递归，如果为 true 表示递归的选择文件
- Regexp，表示要匹配的文件名，如果不写表示加载全部的文件，否则只会加载匹配的文件

当该函数执行后会创建一个模块，例如`"./src/utils sync recursive ^\\.\\/.*$"`，该模块内记录了某个目录下（也就是我这里的 utils 目录）全部可能用到的模块，也就是前面说的 map 对象：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699257806294-6b03c64b-d723-4828-9a44-8b73dadc9c07.png)

该模块会返回一个`webpackContext`函数，该函数会以 utils 目录为基准，然后可以使用该目录下的模块。

```js
const context = require.context("./utils");
const a = context("./a.js");
console.log(a);
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699257899243-f9de409b-5b4c-4af7-bfef-c1f0f7a314ea.png)

所以，`require.context()`函数就是返回一个目录的上下文，上下文中的模块都会形成打包的结果，我们可以通过`require.context()`函数执行后返回的函数直接找到具体的模块。

另外，`require.context()`返回的函数还具有一个`.key()`的方法，该方法会返回一个数组，表示上下文中所有的模块：

```js
const context = require.context("./utils");
const a = context("./a.js");
console.log(a);
console.log(context.keys());
```

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/1%20%E5%B7%A5%E7%A8%8B%E5%8C%96%E4%BD%93%E7%B3%BB/02%20Webpack4/05%20%E8%A1%A5%E5%85%85/_assets/1699258140032-42ad299c-c757-4ce0-aaec-3a5e4101afdf.png)

说了半天，`require.context()`到底有啥用呢？

有的时候我们可以使用`require.context()`来做一些事情，例如 utils 目录下有很多分散的模块，但是我们使用这些模块的时候又希望是整体的使用：

```js
export.a = require("./a")
export.b = require("./b")
export.c = require("./c")
```

这样写好像也没有什么大问题，但是如果某天模块的名称改了或者文件的位置改了，我们还需要手动更改这个文件代码。

这个时候我们就可以粗暴一点，直接把某个目录下所有的模块都进行导入：

```js
const result = require.context("./utils", true, /\.js/);
console.log(result.keys());
// [ './a.js', './b.js', './c.js' ]
```

这样就得到一个数组，然后我们就可以循环的进行导出：

```js
const context = require.context("./utils", true, /\.js/);

for (const key of context.keys()) {
  let filename = key.substr(2); // 得到 a.js
  filename = filename.substr(0, filename.length - 3); // 得到 a
  module.exports[filename] = context(key);
}
```

这样就可以动态的把所有的模块都导入进来了。

所以，以后我们在 Webpack 的工程中如果遇到一个目录下的文件都是为一个功能服务器的，只是人为拆分开的，我们需要在一个地方把所有的模块都进行导入，这个时候就可以使用这个函数。
