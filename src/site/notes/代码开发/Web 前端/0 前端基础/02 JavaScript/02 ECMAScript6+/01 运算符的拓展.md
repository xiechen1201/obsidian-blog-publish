## 🔢 链判断
在实际的开发中，如果一个对象的某个熟悉嵌套非常深，我们就需要一层一层的访问：

```js
message.body.user.firstName;
```

为了安全不产生错误，我们通常还需要添加是否存在的判断：

```js
// 正确的写法
const firstName = (message
  && message.body
  && message.body.user
  && message.body.user.firstName) || 'default';
```

这样的层层判断是非常麻烦的，因此在 ES2020 中引入了「链判断运算符」`?.`。

`?.`可以简化上面的层层判断：

```js
const firstName = message?.body?.user?.firstName || 'default';
```

链运算符直接在调用的时候进行判断，判断左侧的对象是否为`null`或者`undefined`，如果是则不再进行运算，而是直接返回一个`undefined`。

<br/>

链判断也可以判断一个对象的方法是否存在，如果存在则进行调用，否则返回`undefined`:

```js
person?.sayHello();
```

对于对象动态的属性也可以生效：

```js
person?.[expr];
```

使用链判断运算符需要注意的点：

1、短路机制

`?.`本质上是一种短路机制，只要不满足条件则不会往下执行：

```js
a?.[++x]
// 等同于
a == null ? undefined : a[++x]
```

如果`a`为`null`或者`undefined`，则`x`不会进行递增计算。

2、括号的影响

```js
(a?.b).c
// 等价于
(a == null ? undefined : a.b).c
```

如果属性链有圆括号，那么链判断对圆括号外部是没有影响的。也就是说不管`a`是否存在，但是`c`是肯定执行的。

3、报错场合

以下写法是禁止的：

```js
// 构造函数
new a?.()
new a?.b()

// 链判断运算符的右侧有模板字符串
a?.`{b}`
a?.b`{c}`

// 链判断运算符的左侧是 super
super?.()
super?.foo

// 链运算符用于赋值运算符左侧
a?.b = c
```

## 🔢 Null 判断
当读取对象某个熟悉的时候，如果属性是`null`或者`undefined`，某些情况就需要为它们指定一个默认值。

```js
const headerText = response.settings.headerText || 'Hello, world!';
const animationDuration = response.settings.animationDuration || 300;
const showSplashScreen = response.settings.showSplashScreen || true;
```

但是这种情况会产生一个问题：如果某个属性是空字符串、0或者是`false`，那么默认值也是生效的。

为了避免这种情况，ES2020 引入了「Null 判断运算符」`??`。

它的行为类似于`||`，不同的是只有当属性为`null`或者`undefiend`的时候才会返回默认值。

```js
const headerText = response.settings.headerText ?? 'Hello, world!';
const animationDuration = response.settings.animationDuration ?? 300;
const showSplashScreen = response.settings.showSplashScreen ?? true;
```

这个运算符的另一个目的是为了喝链判断运算符进行配合使用，当某个属性为`null`或者`undefiend`的时候就返回默认值：

```js
const animationDuration = response.settings?.animationDuration ?? 300;
```

## 🔢 #! 命令
Unix 的命令行脚本都支持`#!`命令，这个命令放在脚本中的第一行，用来指定脚本的执行器。

例如 Bash 的第一行：

```bash
#!/bin/sh
```

ES2023 为 JS 引入了`#!`命令，这样就可以让 JavaScript 文件被当做“脚本文件”在操作系统里执行。

```js
#!/usr/bin/env node

console.log("Hello World");
```

这样 Unix 命令行就可以直接执行脚本了。

```bash
# 以前执行脚本的方式
$ node hello.js

# hashbang 的方式
$ ./hello.js
```

对于 JavaScript 引擎来说，会把`#!`理解成注释，忽略掉这一行。

当 Shell 收到执行命令，发现 hello.js 不是一个可执行的二进制程序，然后就去读取内容，发现第一行的`#!`，然后就会通过 node 程序执行这个文件。

为什么是`/usr/bin/env node`?

这是因为 node 可能安装在不同的路径下，env 会帮我们从 PATH 里寻找 node 程序的执行路径。

总结：ES2020 引入了 Hashbang 语法（#!），是为了允许 JavaScript 文件以 #! 开头作为脚本解释器指令。JS 引擎会忽略这一行，使 JS 文件可以直接作为可执行脚本运行，增强了与操作系统的兼容性。
