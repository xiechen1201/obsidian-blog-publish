## 什么是流？
流是指数据的流动，数据从一个地方缓缓的「流向」另外一个地方！

例如一个文件、一个图片、一个视频都是可以使用流的方式进行操作。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/3%20%E5%90%8E%E7%AB%AF%E6%9C%8D%E5%8A%A1/00%20Node/_assets/1716805372876-ae172108-66d9-41b3-aa88-c21db9dd6ffc.png)

在 Node 中虽然可以通过`fs.readFile()`来读取文件，但是这样的方式会把一个很大的文件读取到内存当中，而内存的空间是非常宝贵的，所以我们希望读取文件是一点一点的读取，而不是全部读取。

流是有方向的，流的类型有：

- 可读流（Readable）：可读流是从源头读取数据的流；
- 可写流（Writable）：可写流是将数据写入目标的流；
- 双工流（Duplex）：双工流是同时具有可读和可写功能的流。数据可以同时流入和流出双工流；
- 转化流（Transform）：转换流是一种特殊的双工流，它在读写数据的同时可以对数据进行转换或处理；

## 为什么需要流？
1、可以缓慢的读取一个很大的文件。

## 文件流
什么是文件流？

文件流和流的概念一致，是指内存数据和磁盘文件数据之间的流动。例如一个很大的视频文件从磁盘读取到内存就是「可读流」，如果说内存中的一些数据要往文件里面写就是「可写流」。

## 文件可读流
使用以下方法会创建一个文件可读流，用于读取文件的内容：

```js
const fs = require("fs");
// 创建文件可读流
const result = fs.createReadStream(path[, options]);
```

<br/>tips
参数：

- path：读取文件的路径；
- options：选项：
    - encoding：编码格式；
    - start：起始字节；
    - end：结束字节；
    - highWaterMark：每次读取数量；
        * 如果 encoding 有值，该属性表示一个字符数；
        * 如果 encoding 为 null，该属性表示字节数；

返回值：

返回一个 ReadStream 对象，该对象继承 Readable 的类。

<br/>

可读流的事件：

```js
const fs = require('fs');
const path = require('path');

const filename = path.resolve(__dirname, './abc.txt');

const rs = fs.createReadStream(filename, { encoding: 'utf-8', highWaterMark: 10 });

// 文件被打开时触发
rs.on('open', (data) => {
    console.log('文件被打开了', data);
});

// 发生错误时触发
rs.on('error', (data) => {
    console.log('文件读取出错', data);
});

// 读取到一部分数据后触发
// 注册 data 事件后才会真正开始读取
// 根据 options 中的 highWaterMark 属性读取文件指定的数量
// 若指定了编码，则读取到的数据会自动按照编码转换为字符串
// 若没有指定编码，读取到的数据是Buffer
rs.on("data", (data) => {
    console.log('读取到数据', data);
})

// 所有数据读取完毕后触发
rs.on("end", (data) => {
    console.log('读取到数据结束', data);
})

// 文件被关闭后触发
// 可以通过 rs.close() 手动关闭
// 或者读取完成后自动关闭
rs.on('close', (data) => {
    console.log('文件被关闭了', data);
});
```

可读流的方法：

```js
// 暂停文件读取，调用该方法后会触发 pause 事件
rs.pause();
rs.on("pause", (data) => {
    console.log('文件被暂停了', data);
})

// 恢复读取，调用该方法后会触发 resume 事件
rs.resume();
rs.on("resume", (data) => {
    console.log('文件被恢复了', data);
})
```

## 文件可写流
是用以下方法创建一个文件可写流，用于写入文件的内容：

```js
const fs = require("fs");
// 创建文件可读流
fs.createWriteStream(path[, options])
```

<br/>tips
参数：

- path：读取文件的路径；
- options 选项：
    - flags: 操作文件的方式；
        * w：覆盖；
        * a：追加；
        * 其他
    - encoding：编码方式；
    - start：起始字节；
    - end：结束字节；
    - highWaterMark：每次最多写入的字节数，默认是 64kb；

返回值：

返回一个 WriteStream 对象，该对象继承 Writable 的类。

<br/>

可写流的事件：

```js
const fs = require('fs');
const path = require('path');

const filename = path.join(__dirname, './02.txt');

const ws = fs.createWriteStream(filename, {
    flags: 'a', // w覆盖文件 a追加文件
    encoding: 'utf-8', // 默认是 utf-8，如果是 null 需要写入 buffer
    highWaterMark: 10 // 每次最多写入的字节数
});

// 文件被打开时触发
ws.on("open", () => {
    console.log("文件打开");
});

// 文件被关闭时触发
ws.on("close", () => {
    console.log("文件关闭");
})

// 文件发生错误的时候触发
ws.on("error", (err) => {
    console.log(err);
})
```

可写流的方法：

```js
// 写入一组数据，data 可以是字符串或者 Buffer
const flag = ws.write(data);
```

`ws.write()`方法返回一个布尔值：

- true，表示写入通道没有被填满，接下来的数据可以直接写入无需排队；
    - ![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/3%20%E5%90%8E%E7%AB%AF%E6%9C%8D%E5%8A%A1/00%20Node/_assets/1716879304399-9c8d50d5-863c-407f-9f24-9913974ab9af.png)
- false，表示写入通道目前已经被填满，接下来的数据将被写入队列中；
    - ![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/3%20%E5%90%8E%E7%AB%AF%E6%9C%8D%E5%8A%A1/00%20Node/_assets/1716879310824-a4b3d4b3-07b8-42cf-afb7-8820544d50e7.png)

使用该方法的时候要特别注意「背压问题」，因为写入队列是内存中的数据，是有限的！

写入流的背压（backpressure）问题是指在流式数据处理系统中，生产者（数据源）的数据产生速度超过了消费者（数据处理单元）的处理速度，从而导致系统无法有效处理数据。这种情况在处理大量数据或高吞吐量的数据流时尤为常见。

如果不处理背压问题就会导致内存消耗增加、系统性能变慢！

<br/>

例如下面的方式就会产生背压问题：

```js
// 持续的写一个 10M 的数据
for (let i = 0; i < 1024 * 1024 * 10; i++) {
    ws.write('a');
}
```

文件写入流还有一个事件`drain`会在写入队列清空的时候触发：

```js
// 文件写入队列清空的时候触发
ws.on("drain", (err) => {
    console.log(err);
})
```

利用这个时间我们可以优化一下上面的案例：

```js
let i = 0;

write();
function write() {
    // 定一个布尔值，表示写入通道没有被填满
    let flag = true;
    while (i < 1024 * 1024 * 10 && flag) {
        flag = ws.write('a');
        i++;
    }
}

// 当写入队列清空的时候再次执行 write 方法
ws.on('drain', write);
```

文件写入流的`end()`方法：

```js
// 表示结束写入，将自动关闭文件
// 是否自动关闭取决于 autoClose 配置，默认为 true
ws.end([data]);
```

<br/>tips
参数：

- data：可选参数，表示关闭前的最后一次写入；

## 读写联合案例
下面是一个读取文件数据流到另外一个文件中去的读写案例：

```js
const fs = require('fs');
const path = require('path');

const form = path.resolve(__dirname, './03.txt');
const to = path.resolve(__dirname, './04.txt');

const rs = fs.createReadStream(form);
const ws = fs.createWriteStream(to);

// 读取数据
rs.on('data', chunk=>{
  // 写入数据
  const flag = ws.write(chunk);
  // 如果写入速度跟不上，会产生背压
  if( !flag ){
    // 暂停读取
    rs.pause();
  }
})

// 写入队列排空
ws.on('drain', ()=>{
  // 恢复读取
  rs.resume();
})

// 读取关闭
rs.on('close', ()=>{
  // 写入结束
  ws.end();
  console.log('copy success');
})
```

还有一种更加简洁的方式，因为读写都是基于流的操作，NodeJS 提供了`pipe()`管道将可读流链接到可写流：

```js
const fs = require('fs');
const path = require('path');

const form = path.resolve(__dirname, './03.txt');
const to = path.resolve(__dirname, './04.txt');

const rs = fs.createReadStream(form);
const ws = fs.createWriteStream(to);

// 使用管道的方式进行连接
rs.pipe(ws);

// 读取关闭
rs.on('close', ()=>{
  ws.end();
  console.log('copy success');
})
```

该方法可以解决背压问题！！！
