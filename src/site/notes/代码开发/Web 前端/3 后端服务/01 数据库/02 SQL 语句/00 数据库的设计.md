## 🔢 SQL
什么是 SQL？

SQL 的全称是 Structured Query Language 结构化查询语言。

大部分关系型数据库都拥有基本一致的 SQL 语法。

其下又可以细分为：

- DDL：Data Definition Language 数据定义语言；
    - 操作数据库对象：库、表、视图、存储过程；
- DML：Data Manipulation Language 数据操控语言；
    - 操作数据库中的记录；
- DCL：Data Control Language 数据控制语言；
    - 操作用户权限；

为什么要学习 SQL？

几乎所有的数据库都支持 SQL，我们学习 SQL 后就可以操作任何数据库，对数据库、表、表数据进行增删改查。

<u>设置字段的时候常用的字段类型有如下几个：</u>

- 数值类型：
    - bit：占位 1，0 或者 1，false 或者 true；
    - int：占位 32，整数；
    - decimal(M, N)：能够精确计算的实数，M 是总的数字位数，N 是小树位数；
- 字符串类型：
    - char(n)：固定长度为 n 的字符；
    - varchar(n)：长度可变，最大长度位 n 的字符；
    - text：大量的字符；
- 日期类型：
    - date：仅日期；
    - datetime：日期和时间；
    - time：仅时间；

## 🔢 主键与外键
首先我们需要明白什么是数据库的键。

数据库的键是用来唯一标记记录和建立表间关系的重要机制，是关系型数据库的核心概念。

说白了，就好比是数据的身份证号，是唯一的、不可能重复的。

键又分为主键和外键。

主键的作用就是标识表中的每一条记录的。

例如 student 表中 id 字段就是数据的主键：

- 具有唯一性，不可重复；
- 不能被更改；

## 🔢 表关系
在设计表的时候出现几种情况：

1、一对一。

也就是一个 A 对应 一个 B，一个 B 对应一个 A。例如用户表和用户信息表，这个时候可以把任意一张表的主键同时设置为外键。

2、一对多。

也就是一个 A 对应多个 B，一个 B 对应一个 A，A 和 B 是一对多，B 和 A 是多对一的关系。

例如上面示例，班级就是 A，学生就是 B，班级里可以有多少学生。

在 B 表中设置外键，对应到 A 表的主键。

3、多对多。

也就是一个 A 对应多个 B，一个 B 又对应多个 A。例如学生表和老师表，一个学生可以有多个老师，而一个老师又可以教多个学生。

这种情况下，就需要建立一个中间关系表，关系表至少包含两个外键，分别对应到两张表。

## 🔢 三大设计范式
最后再说一下设计表时候的三大范式。

1、原子性。

每个字段必须是不可再分的原子值，每行数据必须具有唯一标识（主键），不允许出现重复的列。

反例：

```plsql
-- 无法直接查询某学生是否选了特定课程，难以统计每门课程的选课人数。

CREATE TABLE 学生选课 (
    学生ID INT,
    学生姓名 VARCHAR(50),
    所选课程 VARCHAR(200) -- 存储如"数学,英语,物理"这样的多值数据
);
```

2、消除部分依赖。

所有非主键字段必须完全依赖于整个主键，需要将部分依赖的字段拆分到新表。

反例：

```plsql
-- 如果课程名称或学分需要修改，必须更新所有相关学生记录，操作繁琐且易出错。

CREATE TABLE 学生成绩 (
    学号 INT,
    课程编号 INT,
    课程名称 VARCHAR(50), -- 只依赖于课程编号
    学分 INT,            -- 只依赖于课程编号
    成绩 INT,
    PRIMARY KEY (学号, 课程编号)
);
```

3、消除传递依赖。

所有非主键字段必须直接依赖于主键，不能存在 A 依赖 B，B 依赖主键的传递依赖关系。

反例：

```plsql
-- 存在"记录ID→产品ID→产品类别→类别折扣"的传递依赖，修改类别折扣时需要更新多条销售记录。

CREATE TABLE 销售记录 (
    记录ID INT PRIMARY KEY,
    产品ID INT,
    产品类别 VARCHAR(50), -- 依赖于产品ID
    类别折扣 DECIMAL(3,2), -- 依赖于产品类别
    销售数量 INT,
    销售日期 DATE
);
```
