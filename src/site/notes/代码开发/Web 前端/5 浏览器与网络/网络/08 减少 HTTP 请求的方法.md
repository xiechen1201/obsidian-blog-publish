首先回顾一下用户输入 URL 后发送的过程：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1658909598185-9c9c24c1-b2fb-42c2-a48e-900a2653e278.png)

1、输入 URL 后回车。

 2、DNS 进行域名解析为服务器相应的 IP 地址。

3、浏览器网络向服务器发起 TCP/IP 连接请求（过程中发生三次握手）。

4、建立 TCP/IP 连接。

5、浏览器网络发起 HTTP 请求。

6、服务端返回响应的资源。

7、下载 HTML 资源。

8、解析 HTML。

9、遇到 HTML 里的资源，再次发起 HTTP 请求，下载资源。

10、时间线的过程（[时间线、解析与渲染](https://www.yuque.com/xiechen/ipqq3d/xsdu45)）。

11、呈现页面。

根据上面的流程可以看到其中最耗费时间的过程就是网络请求的过程，那么如何较少网络的请求呢？

1、资源合并，例如能做雪碧图就做雪碧图，合并 JS 脚本和 CSS 样式代码。

2、使用缓存，减少不必要的请求。

3、资源懒加载，需要使用的时候才请求。

4、减少页面中的静态资源，例如小尺寸的图片转换 Base64 编码。

5、配置多个域名、CDN 加速（你用你的域名，在第三方服务器进行解析，从而生成 CDN 加速域名）。
