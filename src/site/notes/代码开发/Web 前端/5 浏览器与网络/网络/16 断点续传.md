断点续传顾名思义就是表示下载文件的时候如果中断，恢复的时候接着之前进度继续下载即可。

断点续传也可以分为两种情况，一种是下载，一种是上传。

## 🔢 下载
如果要实现下载的时候断点续传，关键是服务器在响应的时候，要在响应头中加入下面的字段：

```http
Accept-Ranges: bytes
```

这个字段向客户端表示：我这次返回的文件是支持部分数据传输的，你只需要告诉我你需要的是哪一部分数据即可，单位是字节。

此时，如果某些支持断点续传的客户端（例如浏览器、迅雷下载器等等）就可以在请求的时候告诉服务器需要的数据范围，具体做法是在请求头中添加下面的字段：

```http
Range: bytes=0-5000
```

也就是表示客户端向服务端发起请求，希望获取 0-5000 字段范围内的数据即可，无需传递全部的数据。

## 🔢 上传
对于上传来说，实现断点续传的思路就是把要上传的文件切分为多个小的数据块，然后再进行上传。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1749439277486-defa4bc2-a9dc-4e64-9044-e8e4b9df0efb.png)

虽然分片上传的整体思路一致，但是它没有一个统一的、具体的标准，因此需要根据我们具体的业务场景制定自己的标准。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1749440221828-5376ecb6-6fc6-49cb-88aa-3a423270315d.png)

MD5 是一种不可逆转的算法，这里使用 MD5 的原因是要对整个文件和文件分片进行编码并作为其唯一的标识。这样服务器就可以根据编码判断出分片的顺序和是否已经上传了。

<br/>

下面将基于这个流程图贴出核心的实现代码。

1、前端让用户选择文件。

2、选择文件后进行分片。

```js
/**
 * 文件分片
 * @param {File} file
 * @returns
 */
async function splitFile(file) {
  return new Promise((resolve) => {
    // 分片尺寸（1M）
    const chunkSize = 1024 * 1024;
    // 分片数量
    const chunkCount = Math.ceil(file.size / chunkSize);
    // 当前chunk的下标
    let chunkIndex = 0;
    // 使用ArrayBuffer完成文件 MD5 编码
    const spark = new SparkMD5.ArrayBuffer();
    const fileReader = new FileReader(); // 文件读取器
    const chunks = []; // 分片信息数组

    // 读取一个分片后的回调
    fileReader.onload = function (e) {
      spark.append(e.target.result); // 分片数据追加到MD5编码器中
      // 当前分片单独的MD5
      const chunkMD5 =
        SparkMD5.ArrayBuffer.hash(e.target.result) + chunkIndex;
      chunkIndex++;
      chunks.push({
        id: chunkMD5,
        content: new Blob([e.target.result])
      });
      if (chunkIndex < chunkCount) {
        loadNext(); // 继续读取下一个分片
      } else {
        // 读取完成
        const fileId = spark.end();
        resolve({
          fileId,
          ext: extname(file.name),
          chunks
        });
      }
    };

    // 读取下一个分片
    function loadNext() {
      const start = chunkIndex * chunkSize,
        end =
        start + chunkSize >= file.size
        ? file.size
        : start + chunkSize;

      fileReader.readAsArrayBuffer(file.slice(start, end));
    }

    /**
     * 获取文件的后缀名
     * @param {string} filename 文件完整名称
     */
    function extname(filename) {
      const i = filename.lastIndexOf(".");
      if (i < 0) {
        return "";
      }
      return filename.substr(i);
    }

    loadNext();
  });
}
```

对于前端来说，最核心的就是这个`splitFile`函数，该函数内调用了 [spark-md5](https://www.npmjs.com/package/spark-md5) 用户保存文件分片的结果和计算分片的 MD5。

4、判断响应内容。

```js
async function uploadPiece() {
  if (!needs) {
    return;
  }

  // 如果是空的，表示全部上传完成
  if (needs.length === 0) {
    // 上传完成
    setProgress();
    // ...
    return;
  }

  // 组装下一个分片信息
  const nextChunkId = needs[0];
  const file = fileInfo.chunks.find((it) => it.id === nextChunkId).content;
  const formData = new FormData();
  formData.append("file", file);
  formData.append("chunkId", nextChunkId);
  formData.append("fileId", fileInfo.fileId);

  // 上传
  const resp = await fetch("http://localhost:8000/api/upload", {
    method: "POST",
    body: formData
  }).then((resp) => resp.json());
  needs = resp.data;

  setProgress();
  uploadPiece();
}
```

5、至此客户端的工作完成。

6、服务端需要根据分片的顺序和已经上传的分片，进行判断，最终组装分片为一个完整的文件即可。
