## 同源策略
同源策略 Same-Origin-Policy(SOP) 是指：Web 浏览器只允许在两个页面有相同的源时，第一个页面的脚本访问第二个页面里的数据这是被许可的！

例如在 http://test.jsplusplus.com/index.html 用 Ajax 请求 http://study.jsplusplus.com/server.php 的数据提示一个错误！

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1658908451960-64761e62-46fb-4d61-89ad-4afecfa801ec.png)

解读上面的错误：

- Access to XMLHttpRequest at：请求跨域。
- http://study.jsplusplus.com/server.php：请求地址。
- from origin 'http://test.jsplusplus.com'：请求来自源。
- been blocked by CORS policy：被跨域资源共享策略( Cross-origin resource sharing )阻止。
- No 'Access-Control-Allow-Origin' header is present on the requested resource：在请求的资源中没有发现“允许跨域”头信息。

如果我们在服务端中设置 Access-Control-Allow-Origin 为响应来源的时候，跨域就不存在了。

那什么情况下会出现跨域呢？

当「协议+域名+端口号」有一个不同的时候就会出现跨域。

```plain
例如服务地址：
http://www.jsplusplus.com

http://study.jsplusplus.com	不同源（域名不一样）
http://www.jsplusplus.com:8080	不同源（端口不一样，http 的端口默认 80， https 默认 443）
https://www.jsplusplus.com	不同源（协议不一样）
http://www.jsplusplus.com/course/index.html	同源
http://www.jsplusplus.com/index/course/index.html	同源
```

同源策略是浏览器的一个安全功能，不同源的客户端脚本在没有明确授权的情况下，不能读写对方资源。只有同源的脚本才能赋予 DOM、读写 Cookie、Session、Ajax 等操作的权限。

只要有 JS 引擎的浏览器都使用同源策略。

<br/>

不受同源策略限制的项：

1、页面的超链接

2、重定向页面

3、表单的提交

4、资源引入 script 脚本、src/link、href/img、src/iframe、src

## 如何解决跨域？

以下内容全部以 http://test2.jsplusplus.com 向 http://test.jsplusplus.com 请求资源为基础。

<br/>

## 1、服务器中转请求
什么是服务器中转请求呢？

假设我们当前的页面域名是 http://test2.jsplusplus.com，当我们去请求 http://test.jsplusplus.com 时就一定会产生跨域。

同源策略是浏览器的限制，但是对服务器是无效的（服务器也可以发起请求），所以我们可以请求一个和我们同源的服务器，然后通过同源的服务器去请求不同源的地址，最后返回数据。

## 2、iframe + document.domain
document.domain 属性表示当前文档的域名，因为 iframe 不受同源策略的限制，所以我们可以利用 iframe 来嵌入一个和接口同源的页面，然后利用 iframe 窗口对象进行 Ajax 请求。

前提是基础域名必须一致！！！

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1659518794331-548721d6-2424-4538-bef4-b16f89d4174a.png)

```js
document.domain = 'jsplusplus.com';

var iframe = document.createElement('iframe')
// 引入和接口同源的页面
iframe.src = 'http://test.jsplusplus.com/index.html'
iframe.id = 'myIframe'
iframe.style.display = 'none'

iframe.onload = function (){
  // contentWindow 表示 iframe 窗口的 window 对象
  var $$ = document.getElementById('myIframe').contentWindow.$;
  $$.post('http://test.jsplusplus.com/getcourses1.php', {status:1}, function(data){
    console.log(data);
  })
}

document.body.appendChild(iframe)
```

```js
var $ = { // 模拟 jQuery 对 Ajax 的封装 }
```

## 3、iframe + window.name
先认识一下 window.name 属性：

1. 每个浏览器窗口都有一个全局变量 window（iframe 标签使用 contentWindow 属性进行获取）
2. 每个 window 对象都有一个 name 属性（注意：一个窗口只有一个 name 属性）
3. 该窗口被关闭前（生命周期内），所有页面共享一个 name 属性并有读写的权限
4. 该窗口在被关闭前，无论载入什么页面，都不会改变 name 值
5. 存储约为 2M 的字符串
6. 如果父级窗口地址源和 iframe 的地址源不同，父级无法通过 iframe.contentWindow.name 获取值，但 iframe 内部不受该规则限制

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1659519485631-3708d361-c2e5-43e4-bcce-12b062a1e21c.png)

```js
var flag = false;
var iframe = document.createElement("iframe");
iframe.src = "http://test.plusplus.com/index.html"; // 指定和接口同源的页面

var getDatas = function () {
  if (flag) {
    // 再次触发 onload 事件后可以拿到数据
    var data = iframe.contentWindow.name;
    console.log(data);
  } else {
    // 第一次触发 onload 事件的时候才开始请求数据
    flag = true;
    setTimeout(function () {
      // 这里又将 iframe 地址更改为和当前页面同源的页面，再次触发 onload 事件
      iframe.contentWindow.location.href = "http://test2.plusplus.com/index2.html";
    }, 500);
  }
};

iframe.onload = getDatas; // 当 iframe 加载就会触发 getDatas 事件
document.body.appendChild(iframe);
```

```js
// 该页面被 iframe 引入就会触发 Ajax 请求
axjax("test.plusplus.com/index.php").then((result) => {
  // 然后设置 window.name 为返回的数据
  window.name = JSON.stringify(result);
});
```

## 4、iframe + postMessage
window.postMessage 接收两个参数：

1、要发送的数据

2、要接受数据的页面，页面要用 onmessage 事件来接收数据

<br/>warning
⚠️ 注意

postMessage 是被接收方发起的，并不是发送方发起的，这个逻辑有点奇怪！

<br/>

window.postMessage 存在的缺点：

1、伪造数据端漏洞

2、容易受到 XSS 攻击

3、兼容性问题

## 6、CORS 跨域
跨域资源共享（Cross-origin resource sharing）

需要后端进行针对性设置允许请求的域名，或者设置`*`表示任何域名都可以访问，但是这样的方式不安全！

以 PHP 举例，任意域名：

```php
header("Access-Control-Allow-Origin: *")
```

单个域名：

```php
header("Access-Control-Allow-Origin: http://test2.jsplusplus.com")
```

多个域名：

```php
$allowed_origins = array("http://test2.jsplusplus.com", "http://test3.jsplusplus.com");
header("Access-Control-Allow-Origin:", $allowed_origins);
```

## 7、JSONP
JSONP：JSON with Padding 跨域获取 JSON 数据的一种非官方的使用模式。

所以作用就是获取数据的！

- JSON 和 JSONP 不是一个类型；
- JSON 是数据交换格式，JSONP 是一种跨域获取 JSON 数据的交互技术，非正式的协议；
- JSON 抓取的资源并不直接是 JSON 数据，而是带有 JSON 数据参数的函数执行；
- JSONP 只能进行 GET 请求；

客户端希望返回：

```json
{"name":"jaky", "age":"20"}
```

JSONP 实际返回：

```js
callback({"name":"jaky", "age":"20"})
```

💺 先对 script 标签的属性进行探究一波：

1、我们在页面使用`<script>`的时候可以引入外部的 JS 文件并调用属性或方法

```js
var a = "Hello";

function test(){
  console.log(a);
}
```

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta http-equiv="X-UA-Compatible" content="IE=edge" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Document</title>
  </head>
  <body>
    <script type="text/javascript" src="./jsonp.js"></script>
    <script type="text/javascript">
      // jsonp.js 里的属性
      console.log(a); // Hello
      // jsonp.js 里的方法
      test(); // Hello
    </script>
  </body>
</html>
```

这是因为`<script>`是阻塞执行的，因为另外的 JS 文件就好比在同一个页面环境注入 JS 脚本。

2、`<script>`还可以加载非 JS 文件

这是因为`<script>`本身就是引用脚本，对于文件是什么格式`<script>`并不在意，`<script>`只在意文件里面的内容，只要内容能够解析就行，如果不能解析就会报错。

```js
var a = "Hello";

function test(){
	console.log(a);
}
```

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta http-equiv="X-UA-Compatible" content="IE=edge" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Document</title>
  </head>
  <body>
    <!-- 将 jsonp.js 改为 jsonp.txt -->
    <script type="text/javascript" src="./jsonp.txt"></script>
    <script type="text/javascript">
      // 这个时候仍然是可以执行的！！！

      // jsonp.txt 里的属性
      console.log(a); // Hello
      // jsonp.txt 里的方法
      test(); // Hello
    </script>
  </body>
</html>
```

4、调用内部的方法

假设 jsonp.txt 文件就是我们的后端服务，那么是不是就可以直接调用我们前端定义好的方法呢？

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta http-equiv="X-UA-Compatible" content="IE=edge" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Document</title>
  </head>
  <body>
    <script type="text/javascript">
      function test(data){
        console.log(data);
      }
    </script>
    <!-- 假如 ./jsonp.txt 就是我们的后端 api 地址 -->
    <script type="text/javascript" src="./jsonp.txt"></script>
  </body>
</html>
```

```js
// 后端地址直接调用前端的 test 方法，且把数据传递回去
test("JS++");
```

结果如下：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E7%BD%91%E7%BB%9C/_assets/1682564323025-5f0dca44-f1b7-4a48-8671-783515b9442c.png)

既然`<script>`能加载其他的文件，`<script>`又不受同源策略的限制，利用这两点我们就可以去请求一个不同源的 api 接口。

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta http-equiv="X-UA-Compatible" content="IE=edge" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Document</title>
  </head>
  <body>
    <script type="text/javascript">
      function getData(data){
        console.log(data); // { a: 1, b: 2 }
      }

      var oScript = document.createElement('script');
      oScript.src = 'http://test.plusplus.com/index.php?callback=getData';
      document.body.appendChild(oScript);
      document.body.removeChild(oScript);
    </script>
  </body>
</html>
```

```php
<?php

  $cb = $_GET['callback'];

echo $cb.'("{ a: 1, b: 2 }")'
```

浏览器是看不到后端的代码的，因为后端的代码在服务器已经被解析了，所以请求只会返回内容，且`<script>`只会解析返回的内容！

这就是 JSONP 的逻辑，利用`<script>`不受浏览器同源策略的限制，将`<script>`的加载路径设置为一个后端的接口地址且拼接一个回调函数，后端开发人员需要拿到我们的回调函数（需要和后端开发人员拟定回调函数的名字）最后调用我们的函数，也可以把`<script>`地址设置为和接口同源的 JS 文件，让同源的 JS 文件去请求接口然后调用方法，但是这样的方式只能对 GET 请求的跨域有效！！！
