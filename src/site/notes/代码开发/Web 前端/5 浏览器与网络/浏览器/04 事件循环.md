如果想要聊清楚事件循环，那就得先了解浏览器！

## 🔢 浏览器的进程模型
## 🔢 > 什么是进程？
在电脑上运行程序的时候，每个程序都有自己的专属内存空间（RAM），可以把这段内存理解为进程。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721894716556-214df53e-b219-4f07-9983-cc228a258d29.jpeg)

每个程序至少有一个进程，进程之间是相互独立的，即使要进行通信，也需要双方同意！

因为进程设计的目的是为了隔离，每个程序自己出现问题都不会影响到其他的程序。

## 🔢 > 什么是线程？
程序有了进程之后才可以运行代码，而运行代码的“人”被称为「线程」。

一个程序的进程至少有一个线程，所以进程开启后会自动创建一个线程来运行代码，该线程被称为主线程。

很多的时候程序比较多复杂，一个程序同时要运行很多块代码，很多任务同时进行一个线程忙不过来，主线程就会启动更多的线程来执行代码，所以一个进程中可以包含多个线程，多个线程共享一块进程。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721897135911-b66940ee-606e-412b-83f0-5aa05da87326.jpeg)

更加具象的理解：

- 进程就好像是一个工厂，线程就好像工厂里面的工人；
- 工厂和工厂之间是相互独立的。
- 多个工人在一个工厂内协作工作，工厂的空间是工人们相互共享的；

## 🔢 > 浏览器有哪些进程和线程？
浏览器是一个多进程多线程的应用程序！

多进程：浏览器内部极其的复杂，为了避免互相影响，同时为了减少连环崩溃的几率（如果只有一个进程，所有的任务都放在一块，很容易导致一个任务奔溃了，影响到其他的任务，导致整个浏览器都崩溃），当浏览器启动后，它会自动启动多个进程。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721897955251-292aff3e-d3eb-439a-bd05-84f965a4e0db.jpeg)

例如我打开我的浏览器任务管理器：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721897797872-f26b610e-b631-49fc-aedf-cec91ce8d2cd.png)

浏览器的主要进程有：

- 浏览器进程：这是浏览器的主进程，复杂管理和协调其他进程。负责用户界面的展示、浏览器选项、地址栏、书签等。浏览器进程也负责管理网络请求、文件访问以及浏览器的整体运行状态。
- 渲染进程
    - 渲染进程启动后，会开启一个「渲染主线程」，主线程负责将 HTML、CSS 和 JavaScript 转换为可以在屏幕上显示的内容。它还处理用户交互和执行页面上的 JavaScript 代码。
    - 默认情况下，浏览器会给每个标签页开启一个新的渲染进程，以保证不用的标签页之间不会相互的影响。
- 网络进程：负责处理所有网络请求，如 HTTP 请求、WebSocket 连接等。网络进程独立于渲染进程，确保网络活动不会阻塞页面的渲染。

## 🔢 渲染主线程是如何工作的？
渲染主线程是最繁忙的线程，需要它处理的工作包括但不限于：解析 HTML、解析 CSS、计算样式、布局、处理图层、每秒把画面画 60 次（60FPS）、执行全局的 JS 代码、执行事件处理函数、执行计时器的回调函数...

既然这么忙，那么渲染进程为什么不启用多个线程来处理这些任务呢？因为没办法！

要处理这么多的任务，主线程遇到一个前所未有的难题：如何调度任务呢？

如果：

- 主线程正在执行 JS 函数，执行到一半的时候用户点击了按钮，主线程应该立即执行点击事件的处理函数吗？
- 主线程正在执行 JS 函数，执行到一半的时候计时器到达了时间，主线程应该立即去执行计时器的回调吗？
- 浏览器进程通知渲染主线程用户点击了按钮，与此同时，某个时期的定时器也到达了时间，渲染主线程应该处理哪一个任务呢？
- ...

于是，渲染主线程提出了一个绝妙的主意来处理问题：排队！

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721900550644-8ab2dd09-03bb-4cb5-a5e8-5c31693032aa.jpeg)

有了排队的机制后执行流程如下：

- 最开始的时候，渲染主线程会进入一个「无限的循环」；
- 每一次循环都会检查「信息队列」中是否有任务存在。如果有任务则取出第一个任务执行，执行完成后进入下一次循环，如果没有则进入休眠状态；
- 其他所有的线程（包括其他进程的线程）都可以随时的向「信息队列」添加任务。新任务会添加到信息队列的末尾。如果添加任务的时候，渲染主线程是休眠的状态，则会将其唤醒然后继续循环执行任务；

这样一来就可以让任务有条不紊的、持续的进行下去了，这样整个循环的过程被称为事件循环（消息循环）。

## 🔢 什么是异步？
代码执行的过程中会遇到一些无法「立即处理」的任务，例如：

- 定时间`setTimeout`、`setInterval`；
- 网络请求 XHR；
- 用户操作需要执行的事件处理任务`addEventListener`；

如果让渲染进程一直等待着这些异步任务的时机，就会导致渲染渲染主线程长期处于「阻塞」的状态，从而导致浏览器「卡死」。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721959732239-9c32ad16-6342-478b-ad23-2576856e756f.jpeg)

<br/>tips
`setTimeout`没有计时器的功能，需要使用计时器的线程，实际上就是一个通知的作用。

<br/>

渲染主线程承担着极其重要的工作，是无论如何都不能被阻塞的！

所以浏览器渲染使用异步来解决这个问题。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721959739976-06fc7bbe-fa1f-4ecc-8bfd-fa9815d93f1a.jpeg)

这样一来提高了生产效率，渲染主线程一直在忙，但是不会被阻塞。

到这里，可以简单的总结一下：

如何理解 JS 的异步？

JS 是一门单线程的语言，这是因为它运行在浏览器的渲染主线程上，而渲染主线程只有一个。

而渲染主线程承担着很多的工作，渲染页面、执行 JS 都在其中运行。

如果使用同步的方式，就极有可能导致主线程产生阻塞，从而导致消息队列中很多其他任务无法得到执行。

这样一来，一方面会导致繁忙的渲染主线程白白消耗时间，另一方面导致页面无法及时更新，给用户造成卡死的现象。

所以浏览器采用异步的方式来避免。具体做法是当某些任务发生时，比如计时器、网络、事件监听，主线程将这些任务交给其他的线程去处理，自身立即结束任务的执行，转而执行后续的代码。当其他线程任务完成时，将事先传递的回调函数包装成任务，加入到消息队列的末尾排队，等待主线程调度执行！

在这种异步模式下，浏览器永远不会阻塞，从而最大限度的保证了单线程的流畅运行。

## 🔢 JS 执行为何会阻塞渲染？
```html
<h1>Hello, HTML!</h1>
<button>change</button>
<script>
  var h1 = document.querySelector('h1');
  var btn = document.querySelector('button');

  // 死循环指定的时间
  function delay(duration) {
    var start = Date.now();
    while (Date.now() - start < duration) {}
  }

  btn.onclick = function () {
    h1.textContent = 'Hello, JavaScript！';
    delay(3000);
  };
</script>
```

以上代码，会在用户点击按钮后页面卡死 3 秒，然后才会把`h1`的内容更改为“Hello, JavaScript！”。

我可以使用事件循环来解释这个问题：

1、`btn.onclick = function`会告诉交互线程来监听按钮的点击，点击后执行`function`函数。

2、当用户点击了按钮，交互线程把`fn`放在信息队列中。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721961407105-53cbb994-4b95-4907-91d2-484b857eadeb.jpeg)

3、渲染主线程被唤醒，开始循环消息队列，取出`fn`到主线程中执行。

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721961456367-44cbaf59-ee1f-4f7a-babc-b6f591dd66d8.jpeg)

4、`h1.textContent = 'Hello, JavaScript！'`会设置 DOM 的文本内容，如果浏览器要显示更新后的内容，浏览器需要进行重新渲染，会产生一个新的任务，需要在信息队列进行排队。

5、循环结束，fn 执行完成，然后主线程从消息队列中读取任务，放到主线程中执行。

6、通过图示，可以知道 JS 和渲染都说在渲染主线程上执行的，所以后续任务都需排队等待。

## 🔢 任务存在优先级吗？
在 JS 中任务不存在优先级，在消息队列中「先进先出」，但是「消息队列」存在优先级！

根据 W3C 的最新解释:

- 每个任务都有一个任务类型，同一个类型的任务必须在一个队列，不同类型的任务可以分属于不同的队列。 在一次事件循环中，浏览器可以根据实际情况从不同的队列中取出任务执行。
- 浏览器必须准备好一个微队列，微队列中的任务优先所有其他任务执行，[详见](https://html.spec.whatwg.org/multipage/webappapis.html#perform-a-microtask-checkpoint)。

以往说起 JavaScript 的异步，最常见的解释是说宏任务和微任务。

但实际上，随着浏览器需要应对日益复杂的页面效果需求，简单的宏任务微任务两条消息队列已经不足以应对。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721962048399-070d4a2f-f444-4f85-a8a4-e8f2990f23f7.png)

<br/>

在目前，谷歌的实现中，至少包含了下面的队列：

- 延时队列，用于存放计时器到达后的回调任务，优先级「中」；
- 交互队列，用于存放用户操作后产生的事件（例如点击事件）处理任务，优先级「高」；
- 微任务队列，用于存放需要最快执行的任务，优先级「最高」；

可以添加任务到微队列的主要方式是使用`Promise`、`MutationObserver`等 API，例如：

```js
// 立即把一个函数添加到微队列
Promise.resolve().then(函数)
```

下面使用事件循环做几道题：

1、说出下面代码的打印结果：

```js
setTimeout(function () {
  console.log(1);
}, 0);

console.log(2);

// 2 1
```

解析：

- 首先渲染主线程会执行全局的 JS 代码，当看到`setTimeout`后通知相关的线程开启一个计时；
- 然后继续往下执行，打印数字 2；
- 当 0 秒后，计时完成将回调函数包装成一个任务推送到「延时队列」中；
- 主线程执行完成后，事件循环机制会查看消息队列，并从「延时队列」中取出延时任务开始执行，打印结果 1；

2、说出下面代码的打印结果：

```js
function delay(duration) {
  var start = Date.now();
  while (Date.now() - start < duration) {}
}

setTimeout(function () {
  console.log(1);
}, 0);

delay(1000);

console.log(2);

// 2 1
```

- 首先渲染主线程会执行全局的 JS 代码，当看到`setTimeout`后通知相关的线程开启一个计时；
- 接着继续往下执行，调用`delay(1000)`函数，`delay(1000)`函数会将主线程卡死 1 秒。这个期间定时线程会将计时器的回调函数推送到「延时队列」中，等待执行；
- 1 秒后`delay(1000)`函数执行完成，继续往下执行，打印数字 2；
- 主线程执行完成后，事件循环机制会查看消息队列，并从「延时队列」中取出延时任务，推入主线程开始执行，打印结果 1；

3、说出下面代码的打印结果：

```js
setTimeout(function () {
  console.log(1);
}, 0);

Promise.resolve().then(function () {
  console.log(2);
});

console.log(3);

// 3 2 1
```

![画板](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1721984061838-ac236f41-2885-496e-808f-52d009a8c879.jpeg)

- 首先渲染主线程会执行全局的 JS 代码，当看到`setTimeout`后通知相关的线程开启一个计时；
- 至少在 0 秒后，计时器线程会将计时器的回调函数推入「延时队列」中；
- 继续执行，`Promise.resolve()`的状态立即落定为`fulfilled`状态，然后将`.then`的回调函数推入「微任务队列」；
- 继续执行，打印结果 3；
- 主线程执行完成后，事件循环机制会查看消息队列，「微任务队列」和「延时队列」都存在任务，但是「微任务队列」优先级比较高，所以先执行微任务打印 2，再执行延时任务打印 1；

4、说出下面代码的打印结果：

```js
function fn1() {
  console.log(1);
  Promise.resolve().then(function () {
    console.log(2);
  });
}

setTimeout(function () {
  console.log(3);
  Promise.resolve().then(fn1);
}, 0);

Promise.resolve().then(function () {
  console.log(4);
});

console.log(5);

// 5 4 3 1 2
```

- 继续往下执行，`Promise.resolve()`的状态立即落定为`fulfilled`状态，然后将`.then`的回调函数推入「微任务队列」；
- 继续执行全局代码，打印 5；
- 线程执行完成后，事件循环机制会查看消息队列，「微任务队列」和「延时队列」都存在任务，首先执行「微任务对立」，打印 4；
- 再执行「延时队列」，先打印出 3，然后又创建了一个`Promise`状态为`fulfilled`，然后将`.then`的回调函数推入「微任务队列」；
- 定时器任务执行完成后，继续进行事件循环机制，从「微任务队列」中取出任务执行，也就是执行`fn1`函数，先打印 1。接着又创建了一个`Promise`状态为`fulfilled`，然后将`.then`的回调函数推入「微任务队列」；
- `fn1()`函数执行完成后，继续进行事件循环机制，从「微任务队列」中取出任务执行，打印出 2，运行结束；

在之前的 JS 事件循环中，执行全局的 JS 代码通常被认定是一个「宏任务」。

对于微任务的执行时机还有另外一种说法：

当每一个「宏任务」执行完成之后，就会清空「微任务」队列，整个过程被看作是一次循环。然后再取出一个「宏任务」（如果有）进行执行，执行完成后，再次清空「微任务」队列。

对于最新的事件循环中，依旧是在每个任务（延时任务或者交互任务）完成后，就会微任务清空队列，同样被看作是一次循环，然后进入下一次事件循环中。

<br/>

5、把上面的案例进行简单的修改：

```js
function fn1() {
  console.log(1);
  Promise.resolve().then(function () {
    console.log(2);
  });
}

setTimeout(function () {
  console.log(3);
}, 0);

Promise.resolve().then(fn1);

console.log(5);

// 5 1 2 3
```
