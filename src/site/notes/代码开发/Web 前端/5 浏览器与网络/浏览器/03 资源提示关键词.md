现代浏览器中在进行页面解析的时候为了减少外部资源对解析过程的阻塞，新增了一些资源提示关键字。

回顾浏览器的解析过程，当浏览器解析的时候遇到`<script>`标签的时候，过去会立即执行这段 JS 代码，如果这个脚本是外部的，则有必须先下载这个 JS 脚本后执行，导致了 HTML 页面解析的阻塞。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739947035441-1940522e-fe8a-4470-bbb8-750b21b3e62f.png)

这是因为 JS 脚本可能会改变 DOM 的结构，所以 DOM 树的生成必须暂停，以保证最终渲染的 DOM 结构是正确的。

回头再看一下 CSS 是否会阻塞渲染呢？

看上去 JS 会阻塞渲染是因为它可以操作 DOM 的节点，那么 CSS 不能操作 DOM 节点，似乎它没有理由阻止解析。

但是如果 JS 脚本中需要获取一些尚未解析的样式信息怎么办？在 JS 中完全可以访问到 DOM 节点的某些样式，或者使用 JS 直接访问 CSSOM。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739947582845-0f3205d3-159a-4c37-b4b1-d7d485dc6c98.png)

所以，CSS 可能会根据文档中外部样式表和 JS 脚本的执行顺序阻止解析。如果在文档中的脚本之前放置了外部样式表，则 DOM 和 CSSOM 对象的构建可能会互相干扰。

当解析器遇到一个 JS 脚本的时候，在脚本执行完成之前无法继续构建 DOM，然而如果这段脚本代码中涉及到和访问了 CSSOM，那么则必须等待 CSS 文件被下载、解析，并且 CSSOM 可用。如果 CSSOM 处于未可用状态，则会阻塞 JS 的执行。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739948326074-9d1c746a-074b-4395-91c9-f8123777480b.png)

所以，CSS 不会直接阻塞 DOM 的构建，但是可能会间接的阻塞 DOM 的构建。

之前讲到过当 DOM 树和 CSSOM 树都准备完成后，才会生成渲染树（Render Tree），浏览器在拥有 DOM 和 CSSOM 之前不会显示任何的内容。这是因为没有 CSS 的页面通常无法使用，如果浏览器向你展示了一个没有 CSS 的凌乱的页面，那么片刻之后就会进入一个有样式的页面，不断变化的内容和突然的视觉变化会给用户带来混乱的用户体验。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739948550151-c408cfe4-cfb4-4b51-8222-7180e56d8f08.gif)

这种不好的体验有一个名字叫做“无样式内容闪现（Flash of Unstyled Content，简称 FOUC）”。

为了解决这些问题，就需要浏览器尽快的交付 CSS 样式，这就是解释了为什么都推荐“顶部样式，底部脚本”的编码方式。

随着现代浏览器的普及，浏览器为我们提供了更加强大的武器--资源提示关键字，如果合理利用可以大幅度的提高页面的加载速度。

## 脚本的加载优化
首先，当使用`async`时，脚本的下载不会阻塞页面渲染，它会在文件下载完成后立即执行，执行的时候会阻塞 DOM 的解析。这意味着脚本的执行顺序无法保证，可能会在其他脚本或元素加载之前执行。适用于独立的、与其他脚本无依赖关系的 JS 文件。

```html
<script async src="script.js"></script>
```

`defer`脚本的下载也不会阻塞页面渲染，但是是在页面解析完成后（即 DOM 完全构建后）再执行，所以执行也不会阻塞 DOM 解析。它可以保证脚本按照在 HTML 中的顺序依次执行，即使脚本是异步加载的。适用于需要在页面加载完成后执行，并且有依赖关系的脚本。

```html
<script defer src="script.js"></script>
```

## preload
`preload`也是一种资源加载优化的关键字，但是它是用在`<link>`标签上的，它通过声明向浏览器声明提前加载资源，当资源真正被使用的时候就可以被立即执行，无需等待网络的消耗。

```html
<link rel="stylesheet" href="style2.css">
<script src="main2.js"></script>

<!-- 使用 preload 替换掉原先的 stylesheet -->
<!-- 并使用as指定资源的类型 -->

<link rel="preload" href="style1.css" as="style">
<link rel="preload" href="main1.js" as="script">
```

上面的代码中，会先加载 style1.css 和 main1.js 文件（但不会执行），在随后的页面渲染中，一旦需要使用它们的时候，它们会立即可用。

`as`属性可选的值：

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739951299791-5c548525-c574-497d-b065-91815c4ecfd4.png)

使用`preload`关键字的一些优点：

- 允许浏览器设置资源加载的优先级，从而允许开发者优化某些资源的交付；
- 让浏览器能够确定资源类型，因此它可以判断将来是否可以复用相同的资源；
- 通过`as`属性可以确定请求是否符合内容安全策略；
- 浏览器可以根据资源类型发送合适的 Accept 请求头（例如 image/webp）；

## prefetch
`prefetch`表示利用浏览器的空闲时间加载未来可能需要用到的资源，通常用于加载非首页的其他页面所需要的资源，以便加快后续页面的首屏加载速度。

`prefetch`加载的资源可以获取非当前页面所需要的资源，并且将其放入缓存至少 5 分钟（无论资源是否会被缓存），并且页面跳转的时候，不会中断未完成的`prefetch`。

用法同`preload`一样：

```html
<link rel="prefetch" href="/path/to/style.css" as="style">

```

另外和`prefetch`有关联的还有一个`dns-prefeatch`，它表示浏览器在用户浏览页面的时候在后台对页面执行 DNS，这样可以减少网络的延迟，因为一旦用户点击链接就已经进行了 DNS 查找。

通过将`rel="dns-prefetch"`标记添加到链接属性，可以将`dns-prefetch`添加到特定 URL。建议在诸如 Web 字体、CDN 之类的东西上使用它。

```html
<!-- Prefetch DNS for external assets -->
<link rel="dns-prefetch" href="//fonts.googleapis.com">
<link rel="dns-prefetch" href="//www.google-analytics.com">
<link rel="dns-prefetch" href="//cdn.domain.com">
```

## prerender
`prerender`和`prefetch`非常的类似，`prerender`同样也会收集用户接下来可能用到的资源，不同的地方在于`prerender`实际上是在后台渲染整个页面。

```html
<link rel="prerender" href="https://www.keycdn.com">
```

## preconnect
`preconnect`表示允许浏览器在 HTTP 请求实际发送到服务器之前设置早期链接。

我们知道浏览器要建立一个链接一般需要经过 DNS 查找、TCP 三次握手 和 TLS 协商（如果是 HTTPS 协议），这些过程也是非常耗时的。所以，`preconnect`就是一项让浏览器能够预先建立一个链接，等到真正需要加载资源的时候就可以直接进行请求了。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739952083642-5c881471-343d-46c8-bc91-f022806b6f70.png)

例如：

```html
<link href="https://cdn.domain.com" rel="preconnect" crossorigin>
```

以上的代码中，浏览器会经过以下的步骤：

- 解释`href`的属性值，判断是否是合法的 URL。如果是合法的 URL，然后继续判断 URL 的协议是否是 http 或者 https，如果不是合法的 URL，则结束处理；
- 如果当前页面 host 不同于`href`属性中的 host，那么将不会带上 Cookie，如果希望带上 Cookie 等信息，可以加上`crossorign`属性；
