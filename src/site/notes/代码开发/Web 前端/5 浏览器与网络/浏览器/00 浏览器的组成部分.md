什么是 Web 浏览器？

Web 浏览器简称为浏览器，是一种用于访问互联网上信息的应用软件。浏览器的主要功能是从服务器检索 Web 资源并显示在 Web 浏览器窗口中。

Web 资源通常是 HTML 文档，但也可能是 PDF、图像、音视频等其他类型的内容。资源的位置是通过 URI（统一资源定位符）指定的。

浏览器包含一些结构良好的组件，这些组件执行一系列任务能够让浏览器窗口显示 Web 资源。

下面我们将讲述一下浏览器的组成部分，以下是关于浏览器的架构图：

一个浏览器中主要的组件有（当然不止这些）：

- User Inerface 用户界面；
- Browser Engine 浏览器引擎；
- Rendering Engine 渲染引擎；
- Networking 网络；
- JavaScript Interpreter JS 脚本解释器；
- UI Backend 用户界面后端；
- Data Persistence 数据存储；

## 🔢 User Interface 用户界面
这个非常的好理解，用户界面就是用于呈现浏览器窗口的部件，例如地址栏、前进后退按钮、书签、顶部的菜单等等。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/5%20%E6%B5%8F%E8%A7%88%E5%99%A8%E4%B8%8E%E7%BD%91%E7%BB%9C/%E6%B5%8F%E8%A7%88%E5%99%A8/_assets/1739841823295-32fcd315-c80b-4851-b75d-99de7161328a.png)

## 🔢 Browser Engine 浏览器引擎
浏览器引擎是 UI 和渲染引擎之间的桥梁，接收来自 UI 的输入，然后通过操纵渲染引擎将网页或者其他资源显示到浏览器中。

## 🔢 Rendering Engine 渲染引擎
负责在浏览器窗口上显示请求的内容。例如用户请求一个 HTML 页面，渲染引擎负责解析 HTML 文档和 CSS，并将解析和格式化的内容显示到屏幕上。

我们平时说的浏览器的内核也就是指这部分内容。目前主流的浏览器渲染引擎（内核）如下：

- Google Chrome：使用 Blink 引擎
    - Blink 是由 Google 开发的开源渲染引擎，它是 WebKit 引擎的一个分支；
- Mozilla Firefox：使用 Gecko 引擎
    - Gecko 是由 Mozilla 开发的开源渲染引擎，主要用于 Firefox 浏览器；
- Apple Safari：使用 WebKit 引擎
    - WebKit 是一个开源的浏览器引擎，最初由苹果开发，并且目前 Safari 浏览器继续使用它。WebKit 曾是 Chrome 的引擎，但 Chrome 在 2013 年切换到 Blink 之后，WebKit 仍然是 Safari 的主要引擎；
- Microsoft Edge：使用 Blink 引擎（从 2020 年起）
    - 2020 年起，微软决定基于 Chromium（Chrome 的开源项目）来重构 Edge 浏览器，因此 Edge 现在使用 Blink 引擎；
- Opera：使用 Blink 引擎
    - Opera 浏览器也从 2013 年起使用 Blink 引擎，因为它基于 Chromium 项目进行开发。之前，Opera 使用过自家的 Presto 引擎；

渲染引擎渲染页面的整体流程，详见：[浏览器的渲染过程](https://www.yuque.com/xiechen/pyimri/vwbky6n0v42wscum)

这里简单总结一下：请求数据 =>> 生成 DOM 树 =>> 生成 CSSOM 树 =>> 合并为 Render 树 ==> 计算布局 =>> 绘制

## 🔢 Networking 网络
该模块负责处理浏览器内的各种网络通信，它使用一组通信协议，例如 HTTP、HTTPS、FTP，同时通过 URL 获取请求的资源。

## 🔢 JavaScript Interpreter JS 脚本解释器
JavaScript 是一种脚本语言，作为前端开发再熟悉不过了，JS 允许我们动态的更新 Web 内容、控制由浏览器的 JS 引擎执行的多媒体和动画图像。

DOM 和 CSSOM 为 JS 提供了一个接口，可以用于更改 DOM 和 CSSOM。由于浏览器不确定特定的 JS 会做什么，所以浏览器遇到`<script>`的时候会立即暂停 DOM 树的构建。

所以每一个 JS 脚本都是一个解析拦截器，会让 DOM 树的构建工作立即停止。

当浏览器从服务器获取到 JavaScript 代码后，JS 引擎会立刻开始分析这些代码。分析的过程会将代码转化成一种计算机可以理解的形式，这种形式被称为抽象语法树（AST）。这个树形结构保存了代码的所有信息。

接下来，这些信息会交给「解释器」来执行。解释器会把这些结构转化为字节码，字节码是计算机能够理解的指令。

这些是即时 (JIT) 编译器，这意味着从服务器下载的 JavaScript 文件在客户端的计算机上实时编译。解释器和编译器是结合在一起的。解释器几乎立即执行源代码；编译器生成客户端系统直接执行的机器代码。

不同的浏览器使用不同的 JS 引擎：各大浏览器使用的 JavaScript 引擎和解释器如下：

- Google Chrome：使用 V8 引擎
    - V8 是 Google 开发的高性能 JavaScript 引擎，负责解析和执行 JavaScript 代码；
- Mozilla Firefox：使用 SpiderMonkey（蜘蛛猴）引擎；
- Apple Safari：使用 JavaScriptCore 引擎（也叫 Nitro）；
- Microsoft Edge：使用 V8 引擎（从 2020 年起）；
- Opera：使用 V8 引擎；

## 🔢 UI Backend 用户界面后端
用于绘制基本的窗口小部件，比如下拉列表、文本框、按钮等等，向上提供公开的接口，向下调用操作系统的用户界面。

## 🔢 Data Persistence 数据存储
这是一个持久层，浏览器可能需要在本地保存各种数据，例如 Cookie。浏览器还指出 Storage、IndexedDB、WebSQL 和 FileSystem 等存储机制。

以上就是浏览器主要的组成部分，我们重点关注「Rendering Engine 渲染引擎」即可。
