本篇文章我们将讲述一下 Vue2 和 Vue3 响应式的变化。

## Vue2 的响应式

Vue2 的响应式使用的是观察者模式，我们可以将观察者模式类比我们生活中的案例。

假设用户对某个品牌的新手机非常的感兴趣，但是由于热度很高店内一致缺货，那么顾客应该如何买到这款最新的手机呢？

1. 顾客每天都去手机店询问最新的情况；
2. 商品到货后对所有的顾客都发一个通知；

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1739241570111-9fd84412-58c7-4cb6-b2a4-63e94f656f8a.png)

我们似乎遇到一个矛盾：要么让顾客浪费时间检查产品是否到货，要么让手机店浪费资源去通知没有需求的顾客，这两种方式都是低效的。

要解决这个问题其实很简单，那就是让有需求的顾客（Watcher）主动订阅即可，之后商店（Dep）只需要在手机到货后给订阅的顾客发送通知就可以了。

## 响应式工作机制

在 Vue2 中，`data`中的数据会被 Vue 遍历生成 getter 和 setter，这样一来当访问或者设置属性的时候，Vue 就有机会做一些别的事情。

每个 Vue 组件实例都有一个对应的 Watcher 实例，它会在组件渲染过程中追踪并记录访问过的数据属性作为依赖。当这些依赖的 setter 被触发时，watcher 会收到通知，进而触发组件的重新渲染。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1739242228826-9995b704-8505-4ff6-9bb1-0ba4eb25cb89.png)

以上内容几个比较重要的点：

1. 劫持数据：通过`Object.defineProperty()`方法来进行数据的劫持，生成 getter 和 setter 从而让获取/设置值的时候可以做一些其他的事情；
2. 发布者：记录依赖，也就是数据和 watcher 之间的映射关系；
3. 观察者：watcher 会被发布者记录，数据发送变化的时候，发布者会通知 watcher，之后 watcher 会执行相应的处理；

## Observer 观察者（劫持数据）

劫持数据对象是 Observer 的工作，它的目标很简单，就是将一个普通的对象转化为响应式对象。

为了实现这一点，Observer 会把对象的每个属性通过`Object.defineProperty()`转化为带有 getter 和 setter 的属性，这样一来当访问或者设置属性的时候，Vue 就有机会做一些别的事情。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1739244082769-2fec06aa-b76a-40f1-907e-80fc20135749.png)

Observer 是 Vue 内部的构造器，我们可以通过 Vue 提供的静态方法进行访问：

```js
Vue.observable(object);
```

在组件的生命周期中，这个事件发生在`beforeCreate`之后，`created`之前。

具体的实现是，它会递归的遍历对象的所有属性，以完成深度的属性转换。由于遍历的时候只能遍历对象当前有的属性，因此无法检测到将来动态增加或者删除的属性。因此，Vue 提供了`set`和`delete`这两个方法，让开发者可以对已有的响应式对象添加或者删除属性。

对于数组，Vue 会更改它的隐式原型，之所以这么做，是因为 Vue 需要监听那些可能需要改变数组内容的方法。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1739244444173-c2f6d0b0-0548-4b07-90ae-16c45cb237e5.png)

总之，Observer 的目标，就是要让一个对象的属性的读取、赋值，内部数组变化都要被 Vue 感知到。

## Dep 发布者

发布者也被称为依赖管理器，对应的英文是 Dependency，简称 Dep。

其中最核心的两个功能：

- 能够添加观察者：当读取响应式对象的某个属性的时候，它会进行依赖收集；
- 能够通知观察者：当改变某个属性的时候，它会派发更新；
    - 对应本小节开头的生活案例，也就是可以通知订阅的用户手机到货了；

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1739245227895-e6b2d843-c484-4a9d-80bf-ac2b6d1d6bd2.png)

## Watcher 观察者

当依赖的数据发送变化的时候，发布者会通知每一个观察者，而观察者需要调用`update`来更新数据。

Vue2 的内部实现中还存在一个 Scheduler 调度器，因为 Dep 通知 Watcher 之后，如果 Watcher 运行对应的函数，就有可能导致函数频繁执行，从而导致效率低下。

试想，如果一个交给 Watcher 的函数，它里面用到了属性`a`、`b`、`c`、`d`，那么这 4 个属性自然会被记录，于是下面的代码将会被触发 4 次更新：

```js
state.a = "new data";
state.b = "new data";
state.c = "new data";
state.d = "new data";
```

这样显然是不合理的，因此，Watcher 收到派发更新的通知后，实际上不是立即执行对应的函数，而是把自己交给一个叫做「调度器」的东西。

调度器维护了一个执行队列，该队列同一个 Watcher 仅会存在一次，队列中的 Watcher 不是立即执行的，它会通过一个叫做`nextTick`的工具方法，把这些需要执行的 Watcher 放入到事件循环的微任务队列中。

也就说，当响应式数据变化时，`render`函数是异步执行的，并且在微任务队列中。

## Vue3 的响应式

变化一：底层 API 的变化。

相比 Vue2 的响应式首当其冲的就是数据拦截的变化：

- Vue2 使用`Object.defineProperty()`进行拦截；
- Vue3 使用 Proxy + getter、setter 的方式进行拦截；

两者的共同点是都可以针对对象的成员进行拦截，都可以实现深度的拦截。

两者的差异点在于拦截的广度不同：

- `Object.defineProperty()`是针对对象「特定属性」的「读写」操作进行拦截，这意味着之后新增或者删除的属性是检测不到的；
- Proxy 则是针对一「整个对象」的「多种操作」，包括属性的读取、赋值、属性的删除、属性描述符的获取和设置、原型的查看、函数的调用等行为都可以进行拦截；

变化二：响应式数据的创建方式。

另外一个对于开发者能明显感知的变化是创建响应式数据的变化：

- Vue2 通过`data`对象来创建响应式数据；
- Vue3 通过`ref()`、`reactive()`等方式来创建响应式数据；

对应的源码如下：

```ts
class RefImpl<T> {
  private _value: T
  private _rawValue: T

  public dep?: Dep = undefined
  public readonly __v_isRef = true

  constructor(
    value: T,
    public readonly __v_isShallow: boolean,
  ) {
    this._rawValue = __v_isShallow ? value : toRaw(value)
    // 有可能是原始值，有可能是 reactive 返回的 proxy
    this._value = __v_isShallow ? value : toReactive(value)
  }

  get value() {
    // 收集依赖 略
    return this._value
  }

  set value(newVal) {
    // 略
  }
}

// 判断是否是对象，是对象就用 reactive 来处理，否则返回原始值
export const toReactive = <T extends unknown>(value: T): T =>
  isObject(value) ? reactive(value) : value;
```

```ts
function createReactiveObject(
  target: Target,
  isReadonly: boolean,
  baseHandlers: ProxyHandler<any>,
  collectionHandlers: ProxyHandler<any>,
  proxyMap: WeakMap<Target, any>,
) {
  // ...

  // 创建 Proxy 代理对象
  const proxy = new Proxy(
    target,
    targetType === TargetType.COLLECTION ? collectionHandlers : baseHandlers,
  )
  proxyMap.set(target, proxy)
  return proxy
}

export function reactive(target: object) {
  // ...

  return createReactiveObject(
    target,
    false,
    mutableHandlers,
    mutableCollectionHandlers,
    reactiveMap,
  )
}
```

变化三：依赖收集的变化。

依赖收集的方式也发生了变化：

- Vue2：Watcher + Dep
    - 每个响应式属性都有一个 Dep 实例，用于做依赖收集，内部包含了一个数组，存储依赖这个属性的所有 Watcher；
    - 当属性值发生变化后，Dep 会通知所有的 Watcher 去做更新操作；
- Vue3：WeakMap + Map + Set
    - Vue3 的依赖收集粒度更细；
    - WeakMap（targetMap）键对应的是响应式对象，值是一个 Map（propMap），这个 Map 的键是该对象的属性，值还是一个 Map（typeMap），这个 Map 的键是属性的各种操作标识，值是一个 Set（depSet），Set 里面存储了依赖这个属性的 effect 函数；

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1739256195518-9a6afd78-d599-4a84-9316-3ee06097c587.png)

总结来说，Vue3 相比 Vue2 的依赖追踪粒度更细，Vue2 依赖收集的是具体的 Watcher（组件），Vue3 依赖收集的是对应的副作用函数。
