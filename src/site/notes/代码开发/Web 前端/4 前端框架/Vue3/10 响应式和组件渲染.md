回顾一下之前的内容：

- 模版的本质：对应的就是`render()`渲染函数，执行之后返回一段虚拟 DOM（用来描述真实 DOM 的数据结构）；
- 响应式的本质：当数据发生变化时，依赖该数据的「函数」重新执行（也包括渲染函数）；

假如`render()`函数运行的时候用到了响应式数据会怎么样呢？

结果其实很简单，那就是这个`render()`函数会和响应式数据进行关联，当响应式数据发生变化的时候，所关联的`render()`函数就会重新运行，从而得到一个新的虚拟 DOM 结构，最后渲染器就根据最新的虚拟 DOM 结构去更新真实的 DOM 结构，从而在视觉感官上看到的是界面的变化。

> [!warning]
>
> 这里说的重新运行`render()`其实还不是最准确的表达，实际上源码内部是和`updateComponent()`函数关联的，这个函数内部调用了`render()`函数。


## 再看模版编译

例如有这么一段 Vue 的代码：

```vue
<template>
  <div>{{ name }}</div>
  <div>{{ age }}</div>
</template>

<script setup>
import { ref } from 'vue';
const name = ref('张三');
const age = ref(18);
</script>
```

在上面的代码中，模版用到了两个响应式数据，在模版中使用 ref 数据是会自动进行解包`.value`属性的，因此这里就相当于读取了`.value`的值，当读取`.value`的值就会产生读取的拦截，这两个响应式数据就会被模版背后所对应的`render()`渲染函数所关联起来，因此也就产生了依赖关系。

有了依赖关系之后，响应式数据的变化就会导致渲染函数（被监控的函数）的重新执行，得到新的虚拟 DOM，从而让视图得到更新。

## Vue 如何实现精准的更新

Vue 的更新是组件级别的，通过响应式能够知道具体是哪个组件更新了。因为响应式数据是和`render()`渲染函数进行关联的，整个`render()`对应的就是一整个组件的结构，后续只要响应式数据一变化，`render()`函数就会重新执行，生成组件新的虚拟 DOM 结构。

如果要知道具体是哪一个节点发生了变化，那么就需要依靠 Diff 算法进行对比了。

## Vue 如何实现数据共享

在 Vue 中可以轻松实现数据的共享，只需要将响应式数据单独提取出来，然后给多个组件提供这个共享数据进行依赖，只要响应式数据一变化，依赖该数据的组件自然也会重新运行整个`render()`，然后渲染器渲染新的 DOM。

例如下面的案例，我们新建一个 /src/store/index.js 的文件，该文件使用`reactive()`创建一个响应式对象：

```js
import { reactive } from 'vue'

export const store = reactive({
  todos: [
    {
      id: 1,
      text: '学习',
      completed: false
    },
    {
      id: 2,
      text: '吃饭',
      completed: false
    }
  ],
  addTodo(todo) {
    this.todos.push(todo)
  },
  toggleTodo(id) {
    const todo = this.todos.find((todo) => todo.id === id)
    if (todo) {
      todo.completed = !todo.completed
    }
  }
})
```

然后创建 AddTodo.vue 组件并使用 store 的方法：

```vue
<template>
  <div class="add-todo">
    <input type="text" v-model="newTodo" placeholder="请输入新的待办事项" />
    <button @click="addTodo">添加任务</button>
  </div>
</template>

<script setup>
import { ref } from 'vue'
import { store } from '../store/index'

const newTodo = ref('') // 记录新增待办事项的名词
const addTodo = () => {
  if (newTodo.value.trim() === '') {
    return
  }
  store.addTodo({
    id: Date.now(),
    text: newTodo.value,
    completed: false
  })
  newTodo.value = ''
}
</script>

<style scoped>
/* 样式略 */
</style>
```

可以看到，两个组件都会把 store 的数据作为渲染函数的依赖，这样后续 store 数据变化的时候就会触发两个渲染函数的更新。

既然我们可以自己实现数据共享，那么 pinia 的作用呢？

理论上组件之间共享公共数据，pinia 确实没有什么作用了。

但是 pinia 是经过完善的测试的，会带来很多附加的价值，例如：

- 开发工具的支持；
- 热更新替换；
- 插件机制；
- 自动补全；
- SSR

相比一个单纯的响应式数据，pinia 语义上面更好一些：

- 一个单独抽出来的 reactive 对象，从语义上来讲可能是任何东西；
- 一个 pinia 对象，从语义上来讲就是全局共享数据的仓库；

这样其实也能一定程度降低开发者的心智负担，别人一看到 pinia 就知道这是数据共享，提高代码的可读性。
