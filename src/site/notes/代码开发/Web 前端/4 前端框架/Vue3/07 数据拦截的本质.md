## 🔢 数据拦截的方式

什么是拦截？

想象一下你在路上开着车，从地点 A 前往地点 B，本来能够一路畅通无阻，顺顺利利的到达地点 B，但是因为你路上不小心违反了交规。例如不小心开着远光灯一路前行，此时就会被警察拦截下来，对你进行批评教育加罚款，最后才能继续前往地点 B。

这就是生活中的拦截，在你做一件事情的中途将你打断，从而能够做一些额外的事情。

什么是数据拦截？

所谓数据拦截，无外乎就是你在对数据进行操作的时候中途被拦截。例如读数据、写数据的时候。

```js
const obj = { name: '张三' };
obj.name; // 正常读数据，直接就读了
obj.name = '李四'; // 正常写数据，直接就写了
```

我们需要一种机制，在读写操作的中途中进行一个打断，从而方便做一些额外的事情。这种机制我们就称为数据拦截。

这种拦截打断的场景其实有很多，例如 Vue 或者 React 里面的生命周期钩子方法，这种钩子方法本质上也是一种拦截，在组件从初始化到正常渲染的时间线里，设置了几个拦截点，从而让开发者作一些额外的事情。

在 JS 中数据拦截的方式有哪些？

1、`Object.defineProperty()`，对应 Vue1.x 和 Vue2.x 中的响应式；

```js
Object.defineProperty(obj, prop, descriptor);
```

- `obj`：要定义属性的对象;
- `prop`：一个字符串或 Symbol，指定了要定义或修改的属性键;
- `descriptor`：属性描述符;
    - `value`设置属性值，默认值为`undefined`;
    - `writable`设置属性值是否可写，默认值为`false`;
    - `enumerable`设置属性是否可枚举，默认为`false`;
    - `configurable`是否可以配置该属性，默认值为`false`。这里的配置主要是针对这么一些点：
        * 该属性的类型是否能在数据属性和访问器属性之间更改；
        * 该属性是否能删除；
        * 描述符的其他属性是否能被更改；
    - `get`取值函数，默认为`undefined`；
    - `set`存值函数，默认为`undefined`；

<br/>warning
⚠️ 注意

数据属性：`value`、`writable`。

访问器属性：`getter`、`setter`。

数据属性和访问器属性默认是互斥。

<br/>

也就说，默认情况下使用`Object.defineProperty()`定义的属性是不可写、不可枚举和不可配置的。

```js
function Student() {
  let stuName = '张三';

  Object.defineProperty(this, 'name', {
    get() {
      return stuName;
    },
    set(value) {
      if (!isNaN(value)) {
        stuName = '张三';
      } else {
        stuName = value;
      }
    }
  });
}

const stu = new Student();
console.log(stu.name); // （触发 get）
stu.name = '李四'; // （触发 set）
console.log(stu.name); // （触发 get）
stu.name = 100; // （（触发 set）
console.log(stu.name); // （触发 get）
```

2、`Proxy()`对应 Vue3.x 中的响应式。

这是 ES6 中新增的一个 API，用于创建一个对象的代理，从而方便拦截和自定义一个基本操作（例如属性的查找、赋值、枚举、函数调用等）。

```js
const p = new Proxy(target, handler);
```

- `target`：要使用 Proxy 包装的目标对象（可以是任何类型的对象，包括原生数组，函数，甚至另一个代理）；
- `handler`：定义代理对象的行为；

该方法返回一个代理对象，之后外部对属性的读写都是针对这个代理对象进行操作。

![](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1726026031857-0b22d8db-52b8-4e00-8559-3714c4ff79f3.png)

```js
function Student() {
  const obj = {
    name: '张三'
  };
  return new Proxy(obj, {
    get(obj, prop) {
      return obj[prop] + '是个好学生';
    },
    set(obj, prop, value) {
      if (!isNaN(value)) {
        obj[prop] = '张三';
      } else {
        obj[prop] = value;
      }
    }
  });
}

const stu = new Student(); // stu 拿到的就是代理对象
console.log(stu.name); // 张三是个好学生（触发 get）
stu.name = '李四'; //（触发 set）
console.log(stu.name); // 李四是个好学生（触发 get）
stu.name = 100; // //（触发 set）
console.log(stu.name); // 张三是个好学生（触发 get）
```

## 🔢 共同点

1、都可以针对对象成员进行拦截。

```js
const obj = {};

let _data = "这是一些数据";
Object.defineProperty(obj, "data", {
  get() {
    console.log("读取data的操作被拦截了");
    return _data;
  },
});

console.log(obj.data); // 这是一些数据（触发 get）
```

```js
const obj = {
  data: "这是一些数据",
  name: "张三"
};

const p = new Proxy(obj, {
  get(obj, prop) {
    console.log(`${prop}的读取操作被拦截了`);
    return obj[prop];
  },
});

console.log(p.data); // 这是一些数据（触发 get）
console.log(p.name); // 张三（触发 get）
```

都可以拦截写入操作：

```js
const obj = {};

let _data = "这是一些数据";
Object.defineProperty(obj, "data", {
  get() {
    console.log("读取data的操作被拦截了");
    return _data;
  },
  set(value){
    console.log("设置data的操作被拦截了");
    _data = value;
  }
});

obj.data = "这是新的数据"; //（触发 set）
console.log(obj.data); // 这是新的数据（触发 get）
```

```js
const obj = {
  data: "这是一些数据",
  name: "张三"
};

const p = new Proxy(obj, {
  get(obj, prop) {
    console.log(`${prop}的读取操作被拦截了`);
    return obj[prop];
  },
  set(obj, prop, value) {
    // 前面相当于是拦截下这个操作后，我们要做的额外的操作
    console.log(`${prop}的设置操作被拦截了`);
    // 后面就是真实的操作
    obj[prop] = value;
  }
});

p.data = "这是新的数据"; //（触发 set）
p.name = "李四"; //（触发 set）
```

2、都可以实现深度拦截。

两者在实现深度拦截的时候，需要自己书写递归来实现，但总而言之能够实现深度拦截的。

```js
const data = {
  level1: {
    level2: {
      value: 100,
    },
  },
};

function deepDefineProperty(obj) {
  for (let key in obj) {

    // 首先判断是否是自身属性以及是否为对象
    if (obj.hasOwnProperty(key) && typeof obj[key] === "object") {
      // 递归处理
      deepDefineProperty(obj[key]);
    }

    // 缓存一下属性值
    let _value = obj[key];
    Object.defineProperty(obj, key, {
      get() {
        console.log(`读取${key}属性`);
        return _value;
      },
      set(value) {
        console.log(`设置${key}属性`);
        _value = value;
      },
      configurable: true,
      enumerable: true,
    });

  }
}

deepDefineProperty(data);
console.log(data.level1.level2.value);
console.log("----------------");
data.level1.level2.value = 200;

/*
  读取level1属性
  读取level2属性
  读取value属性
  100
  ----------------
  读取level1属性
  读取level2属性
  读取value属性
*/
```

```js
function deepProxy(obj) {
  return new Proxy(obj, {
    get(obj, prop) {
      console.log(`读取了${prop}属性`);
      // 递归处理
      if (typeof obj[prop] === "object") {
        // 递归的再次进行代理
        return deepProxy(obj[prop]);
      }
      return obj[prop];
    },
    set(obj, prop, value) {
      console.log(`设置了${prop}属性`);
      // 递归处理
      if (typeof value === "object") {
        return deepProxy(value);
      }
      obj[prop] = value;
    },
  });
}

const proxyData = deepProxy(data);
console.log(proxyData.level1.level2.value);
console.log("----------------");
proxyData.level1.level2.value = 200;

/*
  读取了level1属性
  读取了level2属性
  读取了value属性
  100
  ----------------
  读取了level1属性
  读取了level2属性
  设置了value属性
*/
```

## 🔢 差异点

1、拦截的广度。

Vue3.x 的响应式，从原本的`Object.defineProperty()`替换了`Proxy()`，是因为两者在进行拦截的时候，无论是拦截的目标还是拦截的行为都是不同的：

- `Object.defineProperty()`是针对「对象特定属性」的「读写操作」进行拦截；
- `Proxy()`则是根据「整个对象」的「多种操作」，包括属性的读取、赋值、属性的删除、属性描述符的获取和设置、原型的查看、函数的调用等行为都是可以进行拦截的；

如果是使用`Object.defineProperty()`进行拦截的话，一旦后期给对象新增属性，是无法被拦截到的，因为`Object.defineProperty()`是在设置拦截的时候是针对的特定属性，所以新增的属性是无法拦截。

```js
const person = {};

Object.defineProperty(person, 'name', {
  get() {
    console.log('获取name');
    return this._name;
  },
  set(value) {
    console.log('设置name', value);
    this._name = value;
  },
  configurable: true,
  enumerable: true,
});

person.name = 'John'; //（触发 set）
console.log(person.name); // （触发 get）

person.age = 30; // （不会被 set 拦截）
console.log(person.age); // 30（不会被 get 拦截）
```

但是`Proxy()`就不一样了，它是针对整个对象的，后期哪怕是对这个对象新增属性也是可以被拦截的：

```js
function deepProxy(obj) {
  return new Proxy(obj, {
    // 获取属性
    get(obj, prop) {
      console.log(`读取了${prop}属性`);
      // 递归的再次进行代理
      if (typeof obj[prop] === 'object') {
        return deepProxy(obj[prop]);
      }
      return obj[prop];
    },
    // 设置属性
    set(obj, prop, value) {
      console.log(`设置了${prop}属性`);
      // 递归的再次进行代理
      if (typeof value === 'object') {
        return deepProxy(value);
      }
      obj[prop] = value;
    },
    // 删除属性
    deleteProperty(obj, prop) {
      console.log(`删除了${prop}属性`);
      delete obj[prop];
    },
    // 获取原型
    getPrototypeOf(obj) {
      console.log('拦截获取原型');
      return Object.getPrototypeOf(obj);
    },
    // 设置原型
    setPrototypeOf(obj, proto) {
      console.log('拦截设置原型');
      return Object.setPrototypeOf(obj, proto);
    }
  });
}
```

理解了上面的差异后，就可以理解为什么 Vue2.x 会有`Vue.set()`这个方法了。

2、性能上的区别。

在大多数的情况下，`Proxy()`是高效的。

但是不能完全断定`Proxy()`就一定比`Object.defineProperty()`效率高，这还得看具体的场景：

- 如果需要拦截的「操作类型（比如 get 和 set）比较少，且主要集中在某些特定属性上」，那么`Object.defineProperty()`可能提供更好的性能。

> 但是只针对某个特定属性的拦截场景较少，一般都是需要针对一个对象的所有属性进行拦截。
>
> 此时如果需要拦截的对象结构复杂（例如需要递归到嵌套对象）或者需要拦截的操作种类繁多，那么使用这种方式就会变得复杂且效率低下。
>

- 如果需要全面的拦截对象的各种操作，那么`Proxy()`能够提供更加强大和灵活的拦截能力，尽管可能有一些轻微的性能开销。
