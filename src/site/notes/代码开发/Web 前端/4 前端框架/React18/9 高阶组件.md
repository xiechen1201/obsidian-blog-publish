高阶组件全称是 Higher-Order Components(HOC)，是 React 中组件复用的一种逻辑技巧。

高阶函数本质上就是一个函数，官网还给了一个公式：

`const EnhancedComponent = higherOrderComponent(WrappedComponent);`

高阶组件要做的事情就是，接收一个组件，然后再返回一个新的组件。其在内部会对接收到组件进行一些逻辑拓展。

![代码开发/Web 前端/4 前端框架/React18/_assets/image.png](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/React18/_assets/image.png)

例如我们有三个组件，这三个组件都存在一些公共的逻辑，那么如果每个组件都写一遍逻辑显然是不合理的，所以我们可以进行逻辑抽离。

早期 React 使用的是 Mixins 来解决逻辑复用的问题：

```jsx file:mian.jsx
const mixinDefaultProps = {}
const ExampleComponent = React.createClasss({
  mixins: [mixinDefaultProps],
  render: function(){}
})
```

> Vue2 就使用的是这种逻辑混入方式。

但是 Mixins 也存在一些问题：

- 隐式的依赖关系；
	- 多个组件混用一个文件，可能引入一些不必要的依赖；
- 命名冲突；
	- 如果引入了多个 Mixins 文件可能存在命名冲突的问题；
- 滚雪球式的复杂性；
	- 随着业务的增多，Mixins 的复杂性也会越来越大，耦合性就会变得很高；

所以，React 后来推出了高阶组件。

![代码开发/Web 前端/4 前端框架/React18/_assets/image-1.png](/img/user/%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/React18/_assets/image-1.png)

==在高阶组件中，接收一个组件作为参数，然后在内部添加逻辑，最后返回一个新的组件。==

例如：

```jsx file:ChildCom1.jsx group:group1
import React from 'react';

function ChildCom1(props) {
    return (
        <div>
            子组件1
            姓名：{props.name}
        </div>
    );
}

export default ChildCom1;
```
```jsx file:ChildCom2.jsx group:group1
import React from 'react';

function ChildCom2(props) {
    return (
        <div>
            子组件2
			年龄：{props.age}
        </div>
    );
}

export default ChildCom2;
```

上面的代码中，`ChildCom1`组件接收一个`name`属性，`ChildCom2`组件接收一个`gae`属性，假如我现在想要在两个组件中添加一段销毁创建的日志打印逻辑，很显然这是一段公共的逻辑，我们就可以使用高阶组件实现这个需求。

例如：

```jsx file:withLog.jsx
import { useEffect } from "react";
import { formatDate } from "../utils/tools";

// 高阶组件是一个函数，接收一个组件作为参数
// 返回一个新的组件
function withLog(Com) {
  // 返回的新组件
  return function NewCom(props) {
    // 抽离的公共逻辑
    useEffect(() => {
      console.log(
        `日志：组件${Com.name}已经创建，创建时间${formatDate(Date.now(), "year-time")}`,
      );
      return function () {
        console.log(
          `日志：组件${Com.name}已经销毁，销毁时间${formatDate(Date.now(), "year-time")}`,
        );
      };
    }, []);
    // 一般来讲，传入的组件会作为新组件的视图
    return <Com {...props} />;
  };
}

export default withLog;
```

在上面的代码中，唯一需要注意的是需要把接收到的`props`原封不动的传递给`<Com />`。

有了高阶组件，我们就可以对`ChildCom1`和`ChildCom2`进行拓展了。

```jsx file:app.jsx hl:7-8
import ChildCom1 from "./components/ChildCom1"
import ChildCom2 from "./components/ChildCom2"
import withLog from "./HOC/withLog"
import { useState } from "react"

// 对原有的子组件进行加强操作
const WrapChild1 = withLog(ChildCom1);
const WrapChild2 = withLog(ChildCom2);

function App() {
  const [toggle, setToggle] = useState(true);
  const child = toggle ? <WrapChild1 name="xiejie" /> : <WrapChild2 age={18} />;
  return (
    <div>
      {/* 按钮对两个组件进行切换，查看日志功能 */}
      <button onClick={() => setToggle(!toggle)}>show/hide</button>
      {child}
    </div>
  );
}

export default App;
```

高阶组件也可以进行嵌套，例如此时又有一段计时的公共的逻辑，此时依旧可以抽离高阶组件。

```jsx file:withTimer.jsx
import { useState, useEffect } from "react";

// 高阶组件是一个函数，接收一个组件作为参数
// 返回一个新的组件
function withTimer(Com) {
  // 返回的新组件
  return function NewCom(props) {
    // 抽离的公共逻辑
    const [counter, setCounter] = useState(1);

    useEffect(() => {
      const stopTimer = setInterval(() => {
        console.log(counter);
        setCounter(counter + 1);
      }, 1000);
      return function () {
        clearInterval(stopTimer);
      };
    });

    // 一般来讲，传入的组件会作为新组件的视图
    return <Com {...props} />;
  };
}

export default withTimer;
```

然后在 app.jsx 中就需要进行嵌套使用：

```jsx file:app.jsx
const WrapChild1 = withTimer(withLog(ChildCom1));
const WrapChild2 = withTimer(withLog(ChildCom2));
```

## 现状

高阶组件的出现解决了组件逻辑复用的问题，很多的第三方库也适用了高阶组件。

例如在`react-redux`中的`connect`用法，这里`connect`明显返回的就是一个高阶组件，之后开发者可以传入自己的组件进行组件强化。

```jsx
connect()(MyComponent)
connect(mapState)(MyComponent)
connect(mapState, null, mergeProps, options)(MyComponent)
```

不过 HOC 的出现实际上就是为了解决 Class 组件的公共逻辑问题，但是随着 hook 的出现，函数组件占主流，React 的思想也从面向对象转变为寒暑式编程，抽离公共逻辑基本都是使用 hook 来解决了。
