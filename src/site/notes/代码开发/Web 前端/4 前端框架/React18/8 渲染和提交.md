React 组件在显示到页面上之前，必须经过 React 的渲染，那么什么时候会导致渲染呢？
1. 组件初始化渲染
2. 组件（或者祖先组件）状态发生了变化

对于组件的初始化渲染没有什么可说的，重点是状态的变化。当组件为完成初始化渲染好后，我们可以使用 set 函数（这里指的是`useState()`中解构的 set 函数）对状态进行更改，React 会把这一次的更改「送入队列」。

当 React 处理更新队列中的状态变更时，会重新执行组件的渲染逻辑。渲染过程中，React 会比较新旧 UI 的差异，并计算出更新页面所需的最少 DOM 操作，最终将这些变更应用到页面上。

或许 state （指的是`useState()`中解构的 state）看起来和普通的 JS 对象没有差异，但 state 表现出来的差异更像是一张快照。

```jsx file:main.jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    console.log(count);
  };

  return <button onClick={handleClick}>{count}</button>;
}

// 0
```

这里打印出来的值并不是 1，而是 0，原因上面也说了 state 更像是某个时间节点的一张快照。

可以理解成：

```md
Render#1
count = 0

Render#2
count = 1

Render#3
count = 2
```

每次 Render 都拥有自己的 State Snapshot，而不是共享一个不断变化的变量。 

再比如点击按钮的时候对`count`进行 3 次的自增：

```jsx file:main.jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    console.log(count);
  };

  return (
	  <h1>{count}</h1>
	  <button onClick={handleClick}>+3</button>
  );
}
```

我们会以为当点击按钮的时候`count`会从 0 变为 3，而实际的情况是只会变为 1。

这是因为`Counter()`组件内的快照就是 0，不管这里进行多少次的 set 都是用 0 去操作的，基本上类似于：
- `setCount(0 + 1)`
- `setCount(0 + 1)`
- `setCount(0 + 1)`

执行了 3 次，这就是为什么点击按钮后页面显示的是 1 而不是 3，它只是告诉 React 在下一次更新的时候把`count`渲染为 1，但不会更改当前渲染内的`count`。

假如，我这里加一个定时器呢？

```jsx file:main.jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    setTimeout(()=>{
	    console.log(count);
    }, 3000)
  };

  return <button onClick={handleClick}>{count}</button>;
}

// 0
```

实际的效果是，点击按钮后对`count`自增，但是 3s 后打印的结果依旧是 0，原因主要还是因为 state 是使用用户与之交互时状态的快照进行调度的。

==一个 state 变量的值永远不会在一次渲染的内部发生变化，即使其事件处理函数的代码是异步的。==它的值在 React 通过调用你的组件“获取 UI 的快照”时就被“固定”了。

继续回到上面的案例：

```jsx file:main.jsx
const handleClick = () => {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    console.log(count);
};
```

React 会等到事件处理函数执行完成后再处理 state 的更新，所以这就是为什么函数的渲染发生在所有的`setCount()`之后，这样做的好处是更改多个 state 不会频繁的引起组件的重渲染，而这种表现被称为「批处理」。

如果想要在函数下次渲染之前，多次的更改 state，那么可以给 set 函数传入一个函数：

```jsx file:main.jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount((count) => count + 1);
    setCount((count) => count + 1);
    setCount((count) => count + 1);
  };

  return <button onClick={handleClick}>{count}</button>;
}

```

现在我们在页面上点击按钮的时候，`count`会从 0 直接显示为 3。

在这里，`(count) => count + 1`被称为「更新函数」。

当运行 set 函数的时候，`(count) => count + 1`会被加入队列中，然后等到事件处理函数运行完成后再处理。

```md
# 更新函数队列（伪代码）
[
  (count) => count + 1,
  (count) => count + 1,
  (count) => count + 1
]
```

> [!tip]
> 这里收集的是函数本身，而不是函数的运行结果！

当事件函数运行完成后，会先拿到快照 state（也就是 0），然后根据队列执行更新函数，相当于`0 => 0 + 1`，接着执行第二个、第三个更新函数，并把得到的结果进行传递：
- `1 => 1 + 1`
- `2 => 2 + 1`

为什么`setCount(1)`不行呢？

因为这种写法队列基本上就是：

```md
# 更新函数队列（伪代码）
[
  1,
  1,
  1
]
```

所以，最终的结果也就是 1。

总结：`setCount(1)`表达的是「把状态设置成 1」，`(count) => count + 1`表达的是「拿到最新的 state，在最新状态的基础上 +1，得到最新状态」。
