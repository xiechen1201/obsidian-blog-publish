什么是响应式数据呢？其实就是「被拦截的对象」。

当一个对象被拦截后，针对对象的各种操作也就能够被拦截下来，从而让开发者有机会做一些额外的事情。因此，只要拦截了对象，就可以把这个对象看做是一个响应式数据。

在 Vue3 中创建响应式数据的方式有`ref()`和`reactive()`两种，这两个 API 的背后都是「针对对象」添加拦截。

试想一下，`ref()`为什么可以把基本类型转换为响应式对象呢？在 JS 中实现拦截的方式有两种，要么是`Proxy()`，要么是`Object.definePropery()`，但是这两个方法都是针对对象来进行拦截的，所以大胆的断定一下`ref()`和`reactive()`背后一定也是针对对象来操作的。

那么`ref()`为什么可以接收基本数据类型呢？

回忆`ref()`的使用：

```js
const state = ref(5);
state.value;
```

下面是`ref()`的源码（简单版）：

```ts
function ref(value) {
  return createRef(value, false);
}

function createRef(rawValue, shallow) {
  if (isRef(rawValue)) {
    return rawValue;  // 如果已经是 ref 对象，直接返回
  }
  return new RefImpl(rawValue, shallow);
}

class RefImpl<T> {
  private _value: T
  private _rawValue: T

  public dep?: Dep = undefined
  public readonly __v_isRef = true

  constructor(
    value: T,
    public readonly __v_isShallow: boolean,
  ) {
    this._rawValue = __v_isShallow ? value : toRaw(value)
    // 有可能是原始值，有可能是 reactive 返回的 proxy
    this._value = __v_isShallow ? value : toReactive(value)
  }

  get value() {
    // 收集依赖 略
    return this._value
  }

  set value(newVal) {
    // 略
  }
}

// 判断是否是对象，是对象就用 reactive 来处理，否则返回原始值
export const toReactive = <T extends unknown>(value: T): T =>
  isObject(value) ? reactive(value) : value
```

从上面的代码中可以看出，`ref()`方法其实是实例化了一个`RefImpl`函数，该函数内会调用`toReactive()`方法并把返回结果赋值给`_value`属性。

`toReactive()`方法内又会对数据进行判断，如果是引用数据则调用`reactive()`方法，否则直接返回。

下面是`reactive()`的源码（简单版）：

```ts
export function reactive(target: object) {
  // ...

  return createReactiveObject(
    target,
    false,
    mutableHandlers,
    mutableCollectionHandlers,
    reactiveMap
  );
}

function createReactiveObject(
  target: Target,
  isReadonly: boolean,
  baseHandlers: ProxyHandler<any>,
  collectionHandlers: ProxyHandler<any>,
  proxyMap: WeakMap<Target, any>
) {
  // ...

  // 创建 Proxy 代理对象
  const proxy = new Proxy(
    target,
    targetType === TargetType.COLLECTION ? collectionHandlers : baseHandlers
  );
  proxyMap.set(target, proxy);
  return proxy;
}
```

从上面的代码中可以看出，`reactive()`方法最终会调用`createReactiveObject()`方法创建一个代理对象。

总结：`ref()`和`reactive()`都是针对对象来进行操作的。从源码中可以看出，`ref()`和`reactive()`在实现响应式上的策略有所不同：

- `ref()`使用的是访问器+`Proxy()`的方式；
- `reactive()`使用的是`Proxy()`的方式；

<br/>

下面是几段代码，自行进行判断是会产生拦截，目的是学会判断某个操作是否会产生拦截。

因为只有产生拦截才会有 Vue 依赖收集和派发更新一类的操作。

回顾文章[数据拦截的本质](https://www.yuque.com/xiechen/de54wv/plwueqsprwufzo0t)，有两个 API 能够实现拦截：

- `Object.defineProperty()`
    - 特定的属性的读取操作
    - 特定的属性的赋值操作
- `Proxy()`
    - 读取
    - 赋值
    - 新增
    - 删除
    - ...

首先，我们可以根据上面源码的原理自己实现一下`ref()`和`reactive()`，并在后续的案例中进行调用：

```ts
function isObject(value) {
  return typeof value === 'object' && value !== null;
}

class RefImpl {
  constructor(value) {
    // 判断是否是对象
    this._value = isObject(value) ? reactive(value) : value;
  }

  get value() {
    console.log(`value被读取了～`);
    return this._value;
  }

  set value(newValue) {
    console.log(`value 被设置为${newValue}了～`);
    this._value = newValue;
  }
}

// 深层代理
function deepProxy(value) {
  return new Proxy(value, {
    get(target, key) {
      console.log(`${key}被读取了～`);

      // 如果读取的是对象，则递归代理
      if (isObject(target[key])) {
        return deepProxy(target[key]);
      }
      return Reflect.get(target, key);
    },
    set(target, key, newValue) {
      console.log(`${key}被设置为${newValue}了～`);
      return Reflect.set(target, key, newValue);
    },
    deleteProperty(target, key) {
      console.log(`${key}被删除了～`);
      return Reflect.deleteProperty(target, key);
    }
  });
}

function reactive(value) {
  return deepProxy(value);
}

function ref(value) {
  return new RefImpl(value);
}
```

下面是案例代码，案例1：

```ts
let state = ref(100); // 传递一个基本类型
state; // 不会触发拦截，因为没有调用任何属性
console.log(state); // 不会触发拦截，因为没有调用任何属性
console.log(state.value); // 会触发 get 拦截
console.log(state.a); // 不会触发拦截，因为 state 对象不存在 a 属性
state.a = 3; // 不会触发拦截，因为 state 对象不存在 a 属性
state.value = 200; // 会触发 set 拦截
delete state.value; // 不会触发代理，因为 value 只会针对 set 和 get 进行拦截
state = 3; // 不会触发更新，因为 statue 只会针对 value 属性进行拦截
```

请一定要记住，数据的拦截一定是基于「对属性的操作」，否则不会被拦截。

<br/>

案例2:

```ts
let state = ref({ abc: 123 }); // 传递一个引用类型
state; // 不会触发拦截，因为不操作对象的属性
console.log(state); // 不会触发拦截，因为不操作对象的属性
console.log(state.value); // 会触发 get 拦截
console.log(state.a); // 不会触发拦截，因为 state 不存在 a 属性
console.log(state.value.abc); // 会触发两次 get 拦截，分别是 .value .abc
state.a = 456; // 不会触发拦截，因为只有当操作 .value 属性才会触发拦截
state.value.a = 456; // 会触发两次拦截，分别是 .value 的 get，.a 的 set
delete state.value.a; // 会触发两次，分别是 .value 的 get，.a 的 delete
state.value = 456; // 会触发拦截
delete state.value; // 不会触发拦截，因为 .value 只会针对 get 和 set 进行拦截
state = 456; // 不会触发拦截，因为 statue 只会针对 .value 进行拦截
```

请一定要记住，如果是基本类型只有操作`.value`属性的时候才会被拦截。如果是引用类型，当操作`.value`和对象的某个属性的时候都会被拦截，因为`.value`返回的是一个 Proxy 代理对象。

案例3:

```ts
let state = reactive({}); // 传递一个引用类型
state; // 不会触发拦截，因为不操作对象的属性
console.log(state); // 不会触发拦截
console.log(state.abc); // 会触发 get 拦截
state.abc = 123; // 会触发 set 拦截
state.a = {
  b: {
    c: 3
  }
}; // 会触发 .a 属性的 set 拦截
console.log(state.a.b.c); // 会3次触发拦截，分别是 .a .a.b .a.b.c，因为是深层代理
delete state.a.b; // 会触发2次拦截，分别是 .a 的 set 拦截，.a.b 的 delete 拦截
```

案例4:

```ts
const state = ref({ a: 1 }); // 传递一个引用类型
const k = state.value; // 触发 .value 的 get 拦截
console.log(k); // 不会触发拦截，因为 k 就是一个代理对象，这里没有对代理对象的属性进行操作
k.a = 2; // 触发 a 的 set 拦截
const n = k.a; // 触发 a 的 get 拦截
console.log(n); // 不会触发，因为 n 返回的是一个原始值
```

案例5:

```ts
const state = reactive([1, 2, 3]); // 传递一个引用类型
state; // 不会触发拦截
state.length; // 会触发 .length 的 set 拦截，因为访问了 length 属性
state[0]; // 会触发 set 拦截，因为访问了 0 属性
state[0] = 4; // 会触发 0 的 set
state.push(5);
/*
  会触发拦截，并且触发的比较多，结果如下：
  push被读取了～
  length被读取了～
  3被设置为5了～
  length被设置为4了～

  因为 .push 方法就相当于是在数组的末尾下标新增一项
*/
```

总结：数据的响应式拦截一定是在操作对象的属性后才会被拦截！
