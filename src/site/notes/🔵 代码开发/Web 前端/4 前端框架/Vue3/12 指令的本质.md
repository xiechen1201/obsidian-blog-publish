到目前为止，我们已经接触了大量 Vue 的内置指令，例如：

- `v-if`
- `v-show`
- `v-model`
- `v-for`
- `v-on`
- `v-bind`
- `v-html`
- ...

这些指令，我们都可以在模版中进行使用，并且他们都有各自的含义和用法。那么，这些指令的本质是什么呢？

本篇我讲继续使用 vite-plugin-inspect 这个插件来分析 Vue 模版编译后的代码。

> vite-plugin-inspect 的使用详见：[https://www.yuque.com/xiechen/de54wv/colyic429klr6dto#uTSR4](https://www.yuque.com/xiechen/de54wv/colyic429klr6dto#uTSR4)
>

## 🔢 v-if

例如我在 App.vue 这个文件内编写如下的代码：

```vue
<template>
  <div v-if="type === 1">type 的值为 1</div>
  <div v-else-if="type === 2">type 的值为 2</div>
  <div v-else-if="type === 3">type 的值为 3</div>
  <div v-else-if="type === 4">type 的值为 4</div>
  <div v-else>type 的值不是 1、2、3、4</div>
  <button @click="toggleFunc">Toggle</button>
</template>

<script setup>
import { ref } from 'vue'

const type = ref(1)
function toggleFunc() {
  type.value = Math.floor(Math.random() * 5)
}
</script>
```

当我们在终端运行项目后，会出现两个可访问的 URL 地址：

![](/img/user/%F0%9F%94%B5%20%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1727594684482-25e0fb95-4704-4e63-9141-1768c314d90f.png)

当访问 http://localhost:5173/__devtools__/ 后，并在左边的侧边栏找到 Vite Inspect 模块后，就可以找到 App.vue 文件，接着点击该文件就可以看到编译前后的对比：

![](/img/user/%F0%9F%94%B5%20%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/Vue3/_assets/1727594934866-80cc3540-bf50-4450-a28f-5a82b17e6534.png)

我们把编译后核心的代码提取出来进行分析：

```js
function _sfc_render(_ctx, _cache, $props, $setup, $data, $options) {
  return (_openBlock(), _createElementBlock(_Fragment, null, [
    ($setup.type === 1)
      ? (_openBlock(), _createElementBlock("div", _hoisted_1, "type 的值为 1"))
      : ($setup.type === 2)
        ? (_openBlock(), _createElementBlock("div", _hoisted_2, "type 的值为 2"))
        : ($setup.type === 3)
          ? (_openBlock(), _createElementBlock("div", _hoisted_3, "type 的值为 3"))
          : ($setup.type === 4)
            ? (_openBlock(), _createElementBlock("div", _hoisted_4, "type 的值为 4"))
            : (_openBlock(), _createElementBlock("div", _hoisted_5, "type 的值不是 1、2、3、4")),
    _createElementVNode("button", {
      onClick: $setup.toggleFunc,
      "data-v-inspector": "src/App.vue:7:3"

}
```

根据代码可以看出来，对于`v-if`、`v-else-if`和`v-else`这三个指令背后对应的就是三目运算符写的不同分支。每一次`$setup.type`的值变化，就会导致`_sfc_render()`渲染函数重新执行，然后执行不同的三目分支。

## 🔢 v-for

例如我在 App.vue 这个文件内编写如下的代码：

```vue
<template>
  <div>商品列表</div>
  <ul>
    <li v-for="item in goods" :key="item.id">
        {{ item.name }}-{{ item.price }}
    </li>
  </ul>
</template>

<script setup>
import { ref } from 'vue'

const goods = ref([
  { id: 1, name: '商品1', price: 100 },
  { id: 2, name: '商品2', price: 200 },
  { id: 3, name: '商品3', price: 300 },
  { id: 4, name: '商品4', price: 400 },
  { id: 5, name: '商品5', price: 500 }
])
</script>
```

同样的，我们把编译后核心的代码提取出来进行分析：

```js
function _sfc_render(_ctx, _cache, $props, $setup, $data, $options) {
  return (_openBlock(), _createElementBlock(_Fragment, null, [
    _cache[0] || (_cache[0] = _createElementVNode("div", { "data-v-inspector": "src/App.vue:2:3" }, "商品列表", -1 /* HOISTED */)),
    _createElementVNode("ul", _hoisted_1, [
      (_openBlock(true), _createElementBlock(_Fragment, null, _renderList($setup.goods, (item) => {
        return (_openBlock(), _createElementBlock("li", {
          key: item.id,
          "data-v-inspector": "src/App.vue:4:5"
        }, _toDisplayString(item.name) + "-" + _toDisplayString(item.price), 1 /* TEXT */))
      }), 128 /* KEYED_FRAGMENT */))
    ])
  ], 64 /* STABLE_FRAGMENT */))
}
```

根据代码可以看出，`v-for`指令最终会被改写为`_renderList()`函数的调用，最终生成虚拟 DOM。

> `_renderList()`函数的具体实现，详见：[https://github.com/vuejs/core/blob/main/packages/runtime-core/src/helpers/renderList.ts](https://github.com/vuejs/core/blob/main/packages/runtime-core/src/helpers/renderList.ts)
>

## 🔢 v-bind

例如我在 App.vue 这个文件内编写如下的代码：

```vue
<template>
  <div v-bind:id>dynamicId</div>
</template>

<script setup>
import { ref } from 'vue'
const id = ref('dynamicId')
</script>
```

我们把编译后的核心代码进行分析：

```js
function _sfc_render(_ctx, _cache, $props, $setup, $data, $options) {
  return (_openBlock(), _createElementBlock("div", {
    id: $setup.id,
    "data-v-inspector": "src/App.vue:2:3"
  }, "dynamicId", 8 /* PROPS */, _hoisted_1))
}
```

可以看到这里就是将`$setup.id`的值作为`<div>`元素的`id`属性。这里涉及到了响应式数据的读取，因此`$setup.id`值的变化，就会导致整个渲染函数的重新执行，`<div>`对应的属性值也会发生变化。

## 🔢 v-on

例如我在 App.vue 这个文件内编写如下的代码：

```vue
<template>
  <div>{{ count }}</div>
  <button v-on:click="count++">+1</button>
</template>

<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>
```

同样的，这里将编译后的核心代码进行提取分析：

```js
function _sfc_render(_ctx, _cache, $props, $setup, $data, $options) {
  return (_openBlock(), _createElementBlock(_Fragment, null, [
    _createElementVNode("div", _hoisted_1, _toDisplayString($setup.count), 1 /* TEXT */),
    _createElementVNode("button", {
      onClick: _cache[0] || (_cache[0] = $event => ($setup.count++)),
      "data-v-inspector": "src/App.vue:3:3"
    }, "+1")
  ], 64 /* STABLE_FRAGMENT */))
}
```

这个也很简单，编译结果就是为`<button>`元素添加上了 click 事件，该事件对应的事件处理函数为：

```js
$event => ($setup.count++)
```

## 🔢 总结

通过这些案例我们对比 App.vue 文件编译前后的结果，可以得出一个结论：

最终编译出来的渲染函数，根本不存在什么指令！不同的指令会被编译为不同的处理方式！
