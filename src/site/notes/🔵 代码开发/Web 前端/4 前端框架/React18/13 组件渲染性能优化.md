## shouldComponentUpdate 与 PureComponent

shouldComponentUpdate 与 PureComponent 都和类组件相关，下面看一个类组件的示例：

```jsx
import React, { Component } from "react";

export default class App extends Component {
  constructor() {
    super();
    this.state = {
      counter: 1,
    };
  }

  render() {
    console.log("App 渲染了");
    return (
      <div>
        <h1>App 组件</h1>
        <div>{this.state.counter}</div>
        <button
          onClick={() =>
            this.setState({
              counter: 1,
            })
          }
        >
          +1
        </button>
      </div>
    );
  }
}
```

上面的示例中，就是一个类组件，然后组件的内部有一个 Button 按钮，每次点击的时候都会把 `counter` 设置成 1。

运行代码后，首次会执行一次初始化渲染（这是符合预期的），接着每次点击按钮的时候都会触发一次页面的渲染。

![](/img/user/%F0%9F%94%B5%20%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/React18/_assets/Pasted%20image%2020260807142733.png)

但其实每次点击按钮的时候 `counter` 都没有变化，这就造成了不必要的渲染。

这个时候我们就可以使用 [shouldComponentUpdate](https://zh-hans.legacy.reactjs.org/docs/react-component.html#shouldcomponentupdate) 来进行优化。

当 props 或 state 变化的时候，shouldComponentUpdate 会在重新渲染之前被调用，该函数默认返回一个 `true`，表示「需要重新渲染」，因此当我们添加自定的逻辑某些时候手动返回一个 `false` 就可以避免无意义的重渲染（首次渲染，或者调用 `forceUpdate()` 的时候不会调用该方法）。

使用 shouldComponentUpdate 来优化上面的示例：

```jsx hl:12-25
import React, { Component } from "react";

export default class App extends Component {

  // ...

  /**
   * @param {*} nextProps 新的 props
   * @param {*} nextState 新的 state
   * @returns
   */
  shouldComponentUpdate(nextProps, nextState) {
    // shouldComponentUpdate 会根据返回值来决定是否重新渲染
    // 默认是 true，要重新渲染
    // 如果返回 false，则不会重新渲染
    // 我们就需要将当前的 props 和 state 与新的 props 和 state 进行一个比较
    if (
      objectEqual(this.props, nextProps) &&
      objectEqual(this.state, nextState)
    ) {
      // 如果新旧 props 和 state 都是相同的，那么就返回 false，不需要重新渲染
      return false;
    }
    return true;
  }

  render() {
    console.log("App 渲染了");

    return (
      <div>
        <h1>App 组件</h1>
        <div>{this.state.counter}</div>
        <button
          onClick={() =>
            this.setState({
              counter: 1,
            })
          }
        >
          增加+1
        </button>
      </div>
    );
  }
}
```

这个时候再点击 Button 按钮都不会触发组件的重渲染了。

shouldComponentUpdate 是类组件内部的一个「生命周期」函数钩子，该函数会在组件重渲染之前被调用，可以拿到下次渲染时候的 props 和 state，我们刚刚做的事情就是把新的 props、state 和旧的 props、state 进行对比。

React 官方也提供了 [PureComponent](https://zh-hans.legacy.reactjs.org/docs/react-api.html#reactpurecomponent)，一般情况下也就不需要我们手动的维护 `shouldComponentUpdate` 的逻辑了：

```jsx hl:3
import React, { PureComponent } from "react";

export default class App extends PureComponent {
  constructor() {
    super();
    this.state = {
      counter: 1
    };
  }

  render() {
    console.log("App 渲染了");
    return (
      <div>
        <h1>App 组件</h1>
        <div>{this.state.counter}</div>
        <button
          onClick={() => {
            this.setState({
              counter: 1
            });
          }}>
          增加+1
        </button>
      </div>
    );
  }
}
```

> [!info]
> PureComponent 和 Component 类似，只不过 PureComponent 帮我们实现了 shouldComponentUpdate 的逻辑。不过，PureComponent 内部实现对比的时候依旧采用的是「浅对比」。

如果我们的 state 是一个对象，那么浅对比的时候就会产生问题：

```jsx hl:7-8,18-20,24-27
import React, { PureComponent } from "react";

export default class App extends PureComponent {
  constructor() {
    super();
    this.state = {
      // 把 counter 更改为 todos 数组
      todos: ["做饭", "睡觉", "学习"]
    };
  }

  render() {
    console.log("App 渲染了");
    return (
      <div>
        <h1>App 组件</h1>
        <ul>
          {this.state.todos.map((item, index) => (
            <li key={index}>{item}</li>
          ))}
        </ul>
        <button
          onClick={() => {
            this.state.todos.push("学习");
            this.setState({
              todos: this.state.todos
            });
          }}>
          增加+1
        </button>
      </div>
    );
  }
}
```

这时候无论怎么点击页面的 Button，列表都不会进行更新（因为不会触发重渲染）：

![](/img/user/%F0%9F%94%B5%20%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/React18/_assets/Pasted%20image%2020260807153438.png)

但是打开 React 的 devtools 又发现 `todos` 确实更新了：

![](/img/user/%F0%9F%94%B5%20%E4%BB%A3%E7%A0%81%E5%BC%80%E5%8F%91/Web%20%E5%89%8D%E7%AB%AF/4%20%E5%89%8D%E7%AB%AF%E6%A1%86%E6%9E%B6/React18/_assets/Pasted%20image%2020260807153536.png)

这主要还是因为 PureComponent 内部是进行浅对比的，在浅对比的时候新的 `todos` 和旧的 `todos` 对比的是内存的地址（因为是引用类型），所以认为 `todos` 没有更新也就不会重渲染了。

==正确的做法是按照官方的说明，每次都把引用类型当作是一个不可变的对象，然后赋值为一个新对象，因为新对象和旧对象的内存地址不一样，==对比成立：

```jsx hl:17-22
import React, { PureComponent } from "react";

export default class App extends PureComponent {
  // ...

  render() {
    console.log("App 渲染了");
    return (
      <div>
        <h1>App 组件</h1>
        <ul>
          {this.state.todos.map((item, index) => (
            <li key={index}>{item}</li>
          ))}
        </ul>
        <button
          onClick={() => {
            const newTodos = [...this.state.todos, "学习"];
            this.setState({
              todos: newTodos,
            });
          }}
        >
          增加+1
        </button>
      </div>
    );
  }
}

```

## memo

shouldComponentUpdate 与 PureComponent 主要是优化类组件的渲染性能，如果是函数组件的话又该怎么办呢？

React 提供了 [memo](https://zh-hans.reactjs.org/docs/react-api.html#reactmemo) 让我们来优化函数组件，==memo 是一个 HOC 高阶组件==，如果组件在相同的 props 下返回相同的渲染结果，则可以使用 memo 对组件进行包裹，以此来实现组件记忆化，并提高组件的渲染性能：

```jsx file:app.jsx
import React, { useState } from 'react';
import ChildCom1 from "./components/ChildCom1"

function App() {

  const [counter1, setCounter1] = useState(1);
  const [counter2, setCounter2] = useState(1);

  console.log("App 渲染了");
  return (
    <div>
      <div>{counter1}</div>
      <button onClick={() => setCounter1(counter1 + 1)}>+1</button>
      <ChildCom1 counter={counter2} setCounter={setCounter2} />
    </div>
  );
}

export default App;
```

```jsx file:ChildCom1.jsx
import React from "react"

function ChildCom1(props) {
    console.log("ChildCom1 渲染了")
    return (
        <div>
            <div>ChildCom1</div>
            <div>{props.counter}</div>
        </div>
    );
}

export default ChildCom1;
```

在上面的代码中，App 组件定义了两个 state，并且把 `counter2` 传递给 ChildCom1 组件，如果此时在页面中点击 button 时就会更改 `counter1` ，从而触发 App 组件的渲染，同时 ChildCom1 组件也会跟着重渲染，因为父组件更新了，子组件当然也需要更新。

但是我们可以发现，ChildCom1.jsx 子组件其实没有更新的必要，因为传递给 ChildCom1 组件的 `props` 没有更新，此时我们就可以使用 `React.memo` 进行优化：

```jsx file:ChildCom1.jsx hl:13
import React from "react"

function ChildCom1(props) {
    console.log("ChildCom1 渲染了")
    return (
        <div>
            <div>ChildCom1</div>
            <div>{props.counter}</div>
        </div>
    );
}

export default React.memo(ChildCom1);
```

之后在 App 内部更改 `counter1` 也不会引起 ChildCom1 组件的重渲染了。

> [!tip] 
> 注意，默认情况下只会对复杂对象进行浅层对比，如果想要控制对比的过程，就需要把「比较函数」作为第二个参数传入。

例如，我们把 state 更改为一个引用类型：

```jsx file:App.jsx hl:7
import React, { useState } from 'react';
import ChildCom1 from "./components/ChildCom1"

function App() {

  const [counter1, setCounter1] = useState(2);
  const [stu, setStu] = useState(["张三","李四"]);

  console.log("App 渲染了");

  function clickHandle(){
    setCounter1(counter1 + 1);
    stu.push("王武");
    setStu(stu)
  }

  return (
    <div>
      <div>{counter1}</div>
      <button onClick={clickHandle}>+1</button>
      <ChildCom1 stu={stu} setStu={setStu} />
    </div>
  );
}

export default App;
```

```jsx file:ChildCom1.jsx
import React from "react"

function ChildCom1(props) {
    console.log("ChildCom1 渲染了")
    
    const lis = props.stu.map((it,index)=>(<li key={index}>{it}</li>))
    
    return (
        <div>
            <div>ChildCom1</div>
            <ul>{lis}</ul>
        </div>
    );
}

export default React.memo(ChildCom1);
```

这个示例和我们之前 PureComponent 的示例是类似的，由于是在原来数组上进行更改，数组的内存地址没有变化，所以 ChildCom1 组件并不会更新为最新的 list。

要解决这个问题的思路也是一致的，那就是把 list 当作是一个不可更改的对象，传递一个新对象到 `stu` 而不是在原对象上更改。

```jsx
function clickHandle(){
    setCounter1(counter1 + 1);
    const arr = [...stu];
    arr.push("王武");
    setStu(arr)
}
```

另外，`React.memo` 还支持传入第二个自定义比较函数，例如：

```jsx hl:5
function MyComponent(props) {
  /* 使用 props 渲染 */
}

function areEqual(prevProps, nextProps) {
  /*
	  如果把 nextProps 传入 render 方法的返回结果与
	  将 prevProps 传入 render 方法的返回结果一致则返回 true，
	  否则返回 false
  */
}

export default React.memo(MyComponent, areEqual);
```

## useCallback

正常情况下，如果组件各自维护自己的 state，内部更新是不会相互影响的。例如 App 组件引入了 ChildCom1 和 ChildCom2 组件：

```jsx file:App.jsx
import { useState } from 'react';
import ChildCom1 from "./components/ChildCom1"
import ChildCom2 from "./components/ChildCom2"

import styles from "./css/App.module.css"

function App() {
  const [counter, setCounter] = useState(0);
  console.log("App渲染了")
  
  return (
    <div className={styles.container}>
      <div className={styles.btnContainer}>
        <div>{counter}</div>
        <button onClick={() => setCounter(counter + 1)}>+1</button>
      </div>

      <div className={styles.childComContainer}>
        <ChildCom1 />
        <ChildCom2 />
      </div>
    </div>
  );
}

export default App;
```

```jsx file:ChildCom1.jsx
import { useState } from "react"

function ChildCom1() {
    const [counter, setCounter] = useState(0);
    console.log("ChildCom1 渲染了")
    
    return (
        <div style={{
            width: "200px",
            height: "100px",
            border: "1px solid"
        }}>
            ChildCom1
            <div>{counter}</div>
            <button onClick={() => setCounter(counter + 1)}>+1</button>
        </div>

}

export default ChildCom1;
```

> ChildCom2 和 ChildCom1 组件基本相同，此处省略。

此时点击 button 都只会影响各自内部的 state，数据更新并不会影响同级组件和父级组件。

但是如果 ChildCom1 和 ChildCom2 的数据都来自于 App 组件，那么情况就不一样了。我们把代码进行修改，App 组件为两个组件提供 state 和更改 state 的方法。

```jsx file:App.jsx
import { useState } from 'react';
import ChildCom1 from "./components/ChildCom1"
import ChildCom2 from "./components/ChildCom2"

import styles from "./css/App.module.css"

function App() {
  const [counter, setCounter] = useState(0);
  const [counter1, setCounter1] = useState(0);
  const [counter2, setCounter2] = useState(0);
  console.log("App渲染了")
  
  return (
    <div className={styles.container}>
      <div className={styles.btnContainer}>
        <div>{counter}</div>
        <button onClick={() => setCounter(counter + 1)}>+1</button>
      </div>

      <div className={styles.childComContainer}>
        <ChildCom1 counter={counter1} setCounter={setCounter1}/>
        <ChildCom2 counter={counter2} setCounter={setCounter2}/>
      </div>
    </div>
  );
}

export default App;
```

ChildCom1 接受父组件传递来的数据，更调用父组件传递来的方法来修改数据：

```jsx file:ChildCom1.jsx
function ChildCom1(props) {
    console.log("ChildCom1 渲染了")
    
    return (
        <div style={{
            width: "200px",
            height: "100px",
            border: "1px solid"
        }}>
            ChildCom1
            <div>{props.counter}</div>
            <button onClick={() => props.setCounter(props.counter + 1)}>+1</button>
```

可以看到，当调用父组件传递来的方法来更新 state，由于数据是由父组件向下传递的，就会导致所有的子组件全部重新渲染了。

此时我们可能会想到使用 `React.memo` 来进行优化：

```jsx file:ChildCom1.jsx hl:20
import React from "react"

function ChildCom1(props) {
    console.log("ChildCom1 渲染了")
    
    return (
        <div style={{
            width: "200px",
            height: "100px",
            border: "1px solid"
        }}>
            ChildCom1
            <div>{props.counter}</div>
            <button onClick={() => props.setCounter(props.counter + 1)}>+1</button>
        </div>
    );
}

// 相同的 props 传入的时候该组件不需要重新渲染
export default React.memo(ChildCom1);
```

这样确实可以解决子组件重渲染的问题，但是假如此时 App 组件内部又要给子组件传递一个函数呢？

```jsx file:App.jsx hl:6-8,15-16
function App() {
  // App 组件自身有一个状态
  // ...
  console.log("App 渲染了")

  function test() {
    console.log("test");
  }

  return (
    <div className={styles.container}>
      {/* ... */}

      <div className={styles.childComContainer}>
        <ChildCom1 counter={counter1} setCounter={setCounter1} test={test} />
        <ChildCom2 counter={counter2} setCounter={setCounter2} test={test} />
      </div>
    </div>
  );
}
```

上面的代码中，我们在 App 组件内部定义了一个函数，==由于每次 App 组件重渲染都会重新生成 `test` 函数，所以就会在 ChildCom1 组件的 memo 中被判断为是不同的 props，也就会继续重渲染。==

此时就可以使用 `useCallback` 来解决这个问题：

```jsx
const memoizedCallback = useCallback(
  () => {
    doSomething(a, b);
  },
  [a, b],
);
```

把内联函数和依赖数组项作为参数传递给 `useCallback` 函数，它会返回内联函数的缓存版本，只有当依赖的数据发生变化后，才会生成新的函数。

```jsx file:App.jsx hl:15-19
import React, { useState, useCallback } from 'react';
import ChildCom1 from "./components/ChildCom1"
import ChildCom2 from "./components/ChildCom2"

import styles from "./css/App.module.css"

function App() {

  const [counter, setCounter] = useState(1); // 这是 App 组件自身维护的状态
  const [counter1, setCounter1] = useState(1); // 这是要传递给 ChildCom1 组件的数据
  const [counter2, setCounter2] = useState(1); // 这是要传递给 ChildCom2 组件的数据

  console.log("App组件渲染了")

  // 每次重新渲染的时候，就会生成一个全新的 test 函数
  // 使用了 useCallback 之后，我们针对 test 函数做了一个缓存  
  const newTest = useCallback(function test(){
    console.log("test触发了")
  }, [])

  return (
    <div className={styles.container}>
      {/* 自身的计数器 */}
      <div className={styles.btnContainer}>
        <div>counter:{counter}</div>
        <button onClick={() => setCounter(counter + 1)}>+1</button>
      </div>

      {/* 使用子组件 */}
      <div className={styles.childComContainer}>
        <ChildCom1 counter={counter1} setCounter={setCounter1} test={newTest}/>
        <ChildCom2 counter={counter2} setCounter={setCounter2} test={newTest}/>
      </div>
    </div>
  );
}

export default App;
```

这样就可以保证传递给子组件的 props 和之前是相同的。

> [!tip]
> `useCallback` 是对函数进行缓存。

## useMemo

语法：

```js
const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
```

主要的作用就是返回一个缓存的值。

某些时候，组件中的某些值需要根据 state 来进行一个二次计算（类似于 Vue 中的 Computed），由于函数组件一旦重新渲染，就会导致函数重新执行，导致之前的二次计算也会重新执行一次。例如：

```jsx file:App.jsx
import React, { useState } from 'react';

function App() {
  const [count, setCount] = useState(1);
  const [val, setValue] = useState('');

  console.log("App 渲染了");

  function getNum() {
    console.log('调用了！！！');
    return count + 100;
  }

  return (
    <div>
      <h4>总和：{getNum()}</h4>
      <div>
        <button onClick={() => setCount(count + 1)}>+1</button>
        {/* 文本框的输入会导致整个组件重新渲染 */}
        <input value={val} onChange={event => setValue(event.target.value)} />
      </div>
    </div>
  );
}

export default App;
```

上面的代码中，当 input 输入的时候就会导致 App 组件重新渲染，但是 `getNum()` 函数依赖的 `count` 是没有变化的，`getNum()` 也就没有重新执行的必要。因此我们可以使用 `useMemo` 来解决这个问题：

```jsx file:App.jsx hl:9-12
import React, { useState,useMemo } from 'react';

function App() {
  const [count, setCount] = useState(1);
  const [val, setValue] = useState('');

  console.log("App 渲染了");

  const getNum = useMemo(() => {
    console.log('调用了！！！！！');
    return count + 100;
  }, [count])

  return (
    <div>
      <h4>总和：{getNum}</h4>
      <div>
        <button onClick={() => setCount(count + 1)}>+1</button>
        {/* 文本框的输入会导致整个组件重新渲染 */}
        <input value={val} onChange={event => setValue(event.target.value)} />
      </div>
    </div>
  );
}

export default App;
```

这样我们就对 `getNum()` 进行了缓存，只有当依赖的 `count` 发生变化时，整个`getNum()`函数才会重新执行计算。
